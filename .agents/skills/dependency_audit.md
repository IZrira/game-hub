# Skill: Dependency Audit & Build Verification

## Objective
서드파티 종속성(NPM 패키지 등) 설치 시 발생할 수 있는 소프트웨어 공급망 공격(Supply Chain Attack)을 방어하고, 빌드 전후 보안 취약점 요소를 전수 검사합니다.

## Instructions

1. **종속성 추가 시 보안 검사**:
   - 신규 NPM 모듈이나 외부 라이브러리를 프로젝트에 반영하기 전, 해당 패키지의 주간 다운로드 수 및 GitHub 활동성 등 신뢰성을 간략히 확인하십시오.
   - 패키지 설치 시 `npm install [package-name] --dry-run` 혹은 로컬 캐싱을 이용하고, 즉각 `npm audit`을 실행하여 취약성 수준을 계측하십시오.

2. **빌드 무결성 보장**:
   - `npm run build` 또는 배포 아티팩트 생성 작업을 진행할 때, 개발 코드가 로컬 파일 시스템을 벗어나 비인가된 통신 경로로 패킷을 전송하는 등의 비정상 런타임 행태가 없는지 검토하십시오.
   - 빌드 번들링 결과물(`dist/` 폴더 내부)에 불필요한 설정 파일이나 소스 맵(Source Map)을 통해 중요 로직 및 키가 무단 배포본에 노출되는 현상을 제어합니다. (프로덕션 환경에서는 기본 소스 맵 생성을 통제함)

3. **취약성 검출에 따른 대응 루프**:
   - `npm audit`에서 `High` 또는 `Critical` 등급의 보안 경고가 검출되면, 파이프라인의 다음 단계(DevOps 배포)로의 이행을 보류하고 수정 버전의 패키지 갱신(`npm audit fix`) 또는 안전한 대체 패키지 사용 방안을 개발 엔지니어(`@engineer`)에게 지시하십시오.
