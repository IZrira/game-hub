## 2. Logic Chain
1. **Observation**: `router.tsx` dispatches character detail requests to `CharacterDetailHSR`, `CharacterDetailWW`, and `CharacterDetailNTE`.
2. **Observation**: None of the three character detail page components currently mount a team synergy or recommended team UI card.
3. **Reasoning**: A single reusable `SynergyDeck.tsx` component should be created in `common-hub/components/SynergyDeck.tsx` so that all three hubs can import and mount it cleanly without duplicating UI code.
4. **Observation**: HSR and WW have existing party datasets (`HSR_PARTIES` in `hsr-hub/data/parties/index.ts` and `WW_PARTY_COMBINATIONS` in `ww-hub/data/parties.ts`), whereas NTE has character definitions in `nte-hub/data/index.ts` but no dedicated party file.
5. **Reasoning**: A utility helper (`common-hub/data/synergyManager.ts` or `common-hub/utils/synergyManager.ts`) should query game-specific party datasets based on `gameId` and `characterId`/`characterName`, with a smart fallback mechanism for NTE (or unlisted characters) to construct recommended synergy cards from attribute/role matches.
6. **Observation**: Existing page headers and sections use consistent numerical indexing (`SectionHeader` with `num="04"` or `num="05"`) and glassmorphism styling (`glass-card`).
7. **Reasoning**: `SynergyDeck` must adopt the same `SectionHeader` pattern and `glass-card` aesthetics, passing down the character's active element `theme` object for accent colors and glow effects.
