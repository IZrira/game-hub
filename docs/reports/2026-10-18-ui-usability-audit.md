# 전체 허브 UI·사용 편의성 점검

점검일: 2026-10-18 KST. 로컬 기준 HEAD: `96f05f5`.

대상: 운영 `https://riragamehub.com`의 한국어·로그아웃 공개 화면. 기준은 `DESIGN.md`, 공통 컴포넌트 레지스트리, UX 상태 체크리스트 및 `rira-ui-check`다.

## 결론

현재는 새 테마나 카드 재디자인보다 **원하는 정보까지 도달하는 거리**를 줄이는 것이 우선이다. HSR·WW·NTE의 캐릭터 카드 크기는 이미 같은 수준이다. 바깥 여백을 일괄 축소하거나 모든 카드를 더 작게 만들 필요는 없다.

가장 효과가 클 작업 순서:

1. 홈과 파티 추천의 과도한 소개 영역 축소.
2. 모바일 도감의 검색·필터 배치 정리. 특히 애니모 검색창을 위로 이동.
3. 모바일 상세의 이름·역할·상세 공략 진입을 대표 이미지보다 먼저 또는 가까이 배치.
4. 분석 가이드의 접이식 목차와 현재 읽는 위치 안내.
5. 로딩 상태·한국어 명칭·터치 조작의 세부 정리.

## 실제 확인 범위

브라우저 viewport를 데스크톱 1440×900, 모바일 390×844로 설정했고 NTE 캐릭터 목록은 320×844도 확인했다. 스크롤바 때문에 측정된 body 너비는 각각 1432·382·312px인 화면이 있었다. 브라우저 크기는 점검 후 원래대로 복원했다.

대표 URL 12개:

- `/` — 데스크톱·모바일 첫 화면, 통합 검색.
- `/gallery/hsr/character/feixiao` — 데스크톱 상세.
- `/gallery/ww/character/baizhi` — 데스크톱 상세 및 장비 이동.
- `/gallery/nte/character/감정사` — 데스크톱·모바일 상세.
- `/gallery/hsr?menu=캐릭터` — 모바일 목록.
- `/gallery/ww?menu=캐릭터` — 모바일 목록.
- `/gallery/nte?menu=캐릭터` — 모바일·좁은 화면 목록.
- `/gallery/aniimo/characters` — 데스크톱·모바일 목록, 검색 결과 없음·초기화·비교 선택/제거.
- `/gallery/aniimo/character/탄멍멍` — 모바일 상세 및 형태 전환.
- `/gallery/hsr/guides/damage-formula-guide` — 모바일 본문·게임 메뉴.
- `/gallery/hsr/tierlist` — 모바일 모드·역할 필터 화면.
- `/gallery/ww/parties` — 모바일 소개·검색·파티 카드 구조.

네 허브를 대표 화면으로 점검한 것이며 모든 캐릭터·모든 스킨·모든 메뉴를 전수 검사한 것은 아니다. 운영 댓글·저장·관리자 기능은 조작하지 않았다. 별도 3인 독립 전체 평가는 수행하지 않았다.

## 유지할 부분

- HSR·WW·NTE 모바일 캐릭터 카드는 390px 설정에서 약 **170×227px, 2열**로 일치했다. 게임별 외곽 여백을 바꾸거나 카드만 일괄 축소할 근거가 부족하다.
- WW 상세의 ‘종결 장비’ 버튼은 실제 장비 섹션으로 이동했다. 이동 후 목적지 상단 약 100px, 높이 약 498px인 장비 영역과 공략 링크를 확인했다. 즉시 관찰에서 화면이 안 움직여 보였지만 후속 관찰에서 정상 이동했으므로 고장으로 판정하지 않는다.
- 통합 검색에서 `기염`은 도감과 세팅 공략을 서로 다른 그룹으로 제공한다. 검색창 자동 포커스와 Esc 닫기 후 원래 홈 검색 버튼으로의 포커스 복귀를 확인했다.
- 애니모 검색 결과 없음에는 한국어 안내와 ‘검색 조건 초기화’가 있다. 초기화 후 결과가 복구됐다.
- 애니모 비교 선택 시 비교 영역과 ‘비교 선택됨’ 피드백이 생기고 제거가 가능했다.
- 탄멍멍의 고지 형태 선택 시 이미지 설명·형태·진화 조건이 바뀌었다. 점검 후 기본 형태로 복귀했다.
- HSR 피해 공식 본문은 측정 표본에서 **16px, 행간 26px, 폭 약 292px**였다. 제목·요약·작성/검토일도 구분되어 있어 본문 자체를 더 작게 만들 필요는 없다.
- NTE 320px 목록에서는 body 너비와 scrollWidth가 312px로 같았고 화면을 넘어가는 전체 가로 스크롤은 관찰하지 않았다. 메뉴 자체의 의도된 수평 스크롤과 전체 화면 넘침을 구분한다.

## 개선 1 — 첫 화면에서 게임과 파티를 바로 선택

### 관찰

- 홈의 게임 카드 시작은 1440×900에서 **y≈846px**, 390×844에서 **y≈743px**였다. 데스크톱 카드 크기는 약 267×178px, 모바일은 약 350×178px였다.
- 따라서 첫 화면의 상당 부분이 소개와 검색에 쓰이고 게임 선택은 일부만 보인다. 모바일 제목은 ‘찾으세요’가 끝의 ‘요.’로 한 줄 더 나뉘는 모습도 확인했다.
- WW 파티 추천은 모바일 첫 화면을 `PARTY SYNERGY` 소개 카드가 대부분 차지하고, 아래에 다시 `PARTY BUILDING GUIDE` 안내가 이어졌다. 파티 검색과 실제 조합보다 장식성 소개의 우선순위가 높다.

### 방향

- 게임 카드 크기를 줄이기보다 홈 히어로의 상하 패딩과 제목 줄바꿈을 조정한다.
- ‘게임 선택’과 ‘검색’을 같은 첫 화면의 핵심 행동으로 둔다. 기존 검색과 네 게임 구분은 유지한다.
- WW 파티 소개를 한국어 제목+짧은 한 줄 안내로 압축하고, 자세한 편성 설명은 접을 수 있게 한다. 기존 안내 내용은 삭제하지 않는다.
- 새 색상·서체·테마는 필요 없다.

### 완료 기준

390×844와 1440×900에서 검색과 게임 선택이 명확하게 보이고, 파티 화면은 과도한 소개 없이 실제 조합 또는 검색으로 진입할 수 있어야 한다. 제목의 한 글자 고립 줄바꿈을 확인한다.

## 개선 2 — 모바일 검색과 필터를 먼저

### 관찰

- 애니모 도감의 모바일 검색창은 **y≈972px**, 첫 캐릭터 제목은 **y≈1575px**에 있었다. 큰 소개와 지역 필터를 지난 다음에 이름 검색이 나온다.
- 모바일 HSR 이름 검색은 y≈361px, WW는 y≈321px, NTE는 y≈361px였다.
- HSR·WW·NTE 목록의 첫 카드 시작은 각각 약 650·610·594px였다. 카드 크기는 같지만 필터 개수와 소개/상단 간격에 따라 도달 거리가 달랐다.
- HSR·WW 필터는 작은 제어가 세로로 쌓여 오른쪽 공간이 많이 남는다. 애니모의 원소·포지션·성장·성격 필터는 각 48px 높이로 여러 줄을 차지한다.

### 방향

- 애니모 이름 검색을 소개 아래 첫 제어로 올리고 지역 선택과 부가 필터를 그 아래로 둔다.
- 모바일 기본 상태는 이름 검색+주요 필터 1~2개+‘필터 더 보기’로 간결하게 구성한다. 전체 기능과 선택 상태는 보존한다.
- 접힌 상태에도 ‘적용 필터 수’, ‘전체 초기화’, ‘결과 수’를 제공해 숨겨진 조건을 알 수 있게 한다.
- 기존 공통 필터 패턴을 확인해 확장하고 별도 필터 컴포넌트를 게임별로 복제하지 않는다.

### 완료 기준

모바일 첫 화면에서 이름 검색에 바로 접근하고 필터 적용·해제 후 현재 조건을 알 수 있어야 한다. 뒤로 가기 후 검색어·필터·스크롤 유지 여부도 구현 시 함께 검증한다. 이번에는 이 상태 복원을 전수 검사하지 않았다.

## 개선 3 — 상세 페이지의 ‘빠른 답’ 우선

### 관찰

- NTE 감정사 모바일 대표 이미지는 약 **348×523px**였다. 이름은 y≈649px, 기본 스탯 영역은 y≈893px에서 시작했다.
- 애니모 상세도 대표 이미지가 첫 화면 대부분을 차지하며 이름·속성·형태 제어가 아래로 이어졌다.
- HSR·WW·NTE 데스크톱 상세의 이미지+스탯 2단 구조는 이미 유사했다. 서로 다른 새 상세 디자인을 만들 필요는 없다.

### 방향

- 모바일에서 캐릭터 이름·속성·역할과 기존 ‘상세 공략’ 링크를 먼저 확인할 수 있도록 히어로 내부 순서를 조정한다.
- 대표 이미지는 유지하되 모바일에서 정보형 높이로 제한하는 안과 ‘이미지 크게 보기’ 안을 비교한다. 처음부터 모든 이미지를 더 작게 고정하지 않는다.
- 도감은 사실 데이터, 세팅은 장비·목표 스탯, 분석은 이유·운용으로 역할을 명확히 한다. 같은 설명을 세 화면에 반복하지 않는다.
- 기존 `PageHeader`, `DetailStickyNav`를 재사용한다. 모든 페이지 위에 새 sticky bar를 하나 더 얹는 방식은 피한다.

## 개선 4 — 긴 분석 글의 목차

피해 공식 가이드는 요약과 계수별 제목이 잘 나뉘어 있지만, 모바일에서 원하는 항목까지 바로 이동하는 본문 목차가 확인되지 않았다. `GuideArticle.tsx`에서도 목차/DetailStickyNav 사용을 찾지 못했다.

- 기존 H2를 이용한 접이식 목차를 글 상단에 제공한다.
- ‘요약’, ‘계산 예시’, ‘세팅에 적용’처럼 목적 중심 항목을 먼저 두는 안을 검토한다.
- 본문 글자 크기·행간·읽기 폭은 현재 수준을 유지한다.
- 이동 후 제목이 고정 헤더에 가려지지 않는지, 키보드로 링크를 사용할 수 있는지 검증한다.

## 개선 5 — 로딩·명칭·작은 조작 정리

- 여러 직접 진입에서 공통 헤더/푸터와 `LOADING ARCHIVE...`가 먼저 나타난 뒤 실제 내용이 표시됐다. 측정된 로딩 초수나 서버 원인을 뜻하지는 않지만 사용자에게는 문맥이 사라지는 전환이다. 동일 크기의 섹션 스켈레톤과 ‘캐릭터 정보 불러오는 중’처럼 대상이 분명한 안내가 낫다.
- WW 장비 섹션으로 이동한 직후 일부 아이콘이 검은 공간으로 보였다. 이 관찰만으로 파일 누락·404를 확정하지 않는다. 지연 로딩 중에도 이름과 로딩/오류 상태가 구별되도록 한다.
- 검색창에 `아니모`, `캐릭터 & 아니모`, `TRENDING KEYWORDS`, `4.1 티어표`가 노출됐다. ‘애니모’ 표기를 통일하고, 실제 갱신 근거가 없다면 ‘인기’보다 ‘빠른 검색’ 같은 정직한 라벨을 사용한다. 버전 고정 추천어도 현재 콘텐츠와 대조한다.
- 모바일 전체 메뉴에서 확인된 항목은 검색·홈·로그인이었다. 게임 전환은 홈을 경유해야 하므로 현재 게임명 옆의 기존 탐색 위치에 게임 전환을 모을지 검토한다. 당장 모든 화면에 네 개의 큰 게임 버튼을 추가할 필요는 없다.
- 모바일 일부 상단 조작은 28~34px 높이였다. 검색/필터 48px 높이는 유지하고 작은 아이콘은 주변 간격과 터치 편의성을 검토한다. 이번 결과로 WCAG 위반이나 전체 적합성을 단정하지 않는다.

## 다음 구현 묶음 제안

**1차: 홈+WW 파티의 소개 압축, 애니모 검색 위치 개선.** 기존 외곽 여백과 카드 크기는 유지하고 해당 소개 영역만 조정한다. 탐색 목적과 직접 연결되어 우선순위가 가장 높다.

**2차: 공통 모바일 필터 접기와 결과 수/초기화 표시.** 허브별 이름만 다르고 조작 방식은 같게 한다.

**3차: 상세 모바일 히어로의 빠른 정보와 분석 목차.** 원본 콘텐츠·이미지·추천 순서는 보존한다.

**4차: 로딩 상태와 명칭 정리.** 기능 실패를 숨기거나 콘텐츠를 삭제해 가벼워 보이게 하지 않는다.

## 수행·미검증

이번 작업은 UI 진단과 개선 방향 정리다. 프로젝트 소스·데이터는 수정하지 않았고 이 보고서만 추가했다. Notion 동기화·타입 검사·테스트·빌드·commit·push·새 배포는 실행하지 않았다. 기존 AGENTS.md 및 미추적 보고서를 보존했다.

실제 모바일 기기, 터치 제스처, 200% 확대, 모든 다국어, 네트워크 실패 주입, 전체 대비 측정, 로그인·댓글·관리자 쓰기, 모든 페이지의 키보드 순서·이미지 전수 검증은 미수행이다. 점검한 대표 화면의 결과를 사이트 전체 접근성/보안/성능 점수로 확대하지 않는다.
