# WW 이미지 요청 실패·지연 복구

## 범위와 근거

사용자 스크린샷에서 WW 재료 일부의 지연 표시와 깨진 이미지 표시를 확인했다. 새로고침 시 복구된다는 사용자 관찰이 있다. 특정 요청의 HTTP 실패 코드나 CDN 과부하는 확보하지 못했으므로 원인을 확정하지 않는다. 이전 로컬 JSON 요청 160회/최대 동시20회 오류0은 외부 이미지 장애 검증이 아니다.

## 변경

- WW ItemIcon과 상세 대표 이미지에 RecoverableImage 적용. 크기·스타일·수량·라벨·게임 데이터는 유지.
- 정확한 공개 저장소 prefix에 대해서만 같은 파일의 cdn.jsdelivr → fastly.jsdelivr → raw.githubusercontent → 로컬 unknown 순으로 복구한다. 다른 재료나 화폐 이미지로 바꾸지 않는다.
- 화면 근접 lazy 이미지 및 eager 이미지는 시도당 8초 무응답 시 다음 후보로 진행한다. 최대 원본 포함 원격3회, 이후 중립 대체 이미지로 종료한다. 성공·교체·언마운트 시 타이머 정리. 화면 밖 lazy 이미지는 타이머를 미리 돌리지 않는다.
- 다른 게임 ItemIcon의 기존 동작은 변경하지 않는다. 전체 이미지 자체 호스팅이나 캐릭터 데이터 병렬 로딩은 이번 범위 밖이다.

## 검토 및 검증

성능·보안·UX 에이전트가 독립적으로 읽기 전용 검토했다. 성능 담당이 지적한 lazy 이미지의 DOM 교체 후 관측 누락은 attempt별 observer 재부착과 회귀 테스트로 보완했다. 보안 담당은 고정 HTTPS 제공자·공개 파일 경로·횟수 제한과 기존 CSP 허용 범위를 확인했으며 정책 완화는 하지 않았다. UX 담당은 화폐 오표시 제거 및 크기·내용 보존을 확인했다. 실제 운영 가속률이나 장애 CDN 복구 실측으로 확대하지 않는다.

회귀 검사는 동일 이미지 경로 복구·최종 종료, 재료 수량/의미 보존, source 변경 초기화, 클릭 유지, 8초 timeout, 성공 및 unmount 정리, lazy 관측 재부착을 포함한다. 타입·전체 테스트·production build·SEO/성능 예산·diff 검사 결과 및 CI/배포 결과는 완료 보고에 명시한다. Notion 동기화와 운영 DB 변경 없음.

## 남은 한계

모든 원격 후보가 멈추면 최종 대체 이미지까지 약24초가 걸릴 수 있다. 빠른 재시도가 성공을 보장하지 않으며, CDN별 실패 상태·사용자 환경에서의 느린 네트워크와 첫 진입 문제는 추가 관측이 필요하다. 실제 장애 주입은 단위 테스트에서 수행했고 운영 서버에 부하·장애를 주입하지 않았다.
