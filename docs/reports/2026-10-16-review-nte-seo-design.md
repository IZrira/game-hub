## 1차 판정

**소스·회귀 검토 범위 승인. 실제 화면·운영 색인 해결은 아직 미검증이다.**

아래는 모바일 결함 추가 수정 이전에 고정한 1차 검토다. 후속 변경과 공용 브라우저 관찰은 별도 절에 구분한다.

- NTE 상세의 SEO URL과 마지막 breadcrumb만 기존 사이트맵의 이름 기반 경로로 통일했다. 파티 페이지도 자기 URL과 현재 6속성 메타 설명만 명시했다. 대표 이미지·스킬·파티 카드·스타일·사용자 조작 코드는 변경하지 않았다.
- 파티 원본 `nte-hub/data/parties.ts`와 기존 NTE 사이트맵의 개별 URL 변경은 없다. 초기 HTML 생성만 원본의 실제 추천 목록을 읽도록 바꿨다. 새 캐릭터·조합·순서를 임의로 만들거나 동적 fallback 생성 결과를 정식 추천으로 승격하지 않는다.
- `nte-party-prerender.test.ts`는 파서 결과와 런타임 원본의 전체 동등성, 6개 파티의 원래 순서, 24개 멤버·18개 대체 멤버의 이름/역할/순서, 설명·분류·태그·장점·주의점 보존을 검사한다. 링크도 공개된 이름 경로만 사용하도록 검사한다.
- `nte-page-seo.test.tsx`의 실제 페이지 렌더 검사는 이름·UUID 입력 모두에서 같은 이름 canonical 입력을 확인하고, 파티 페이지의 기존 카드 제목 전체와 순서를 원본 배열에 대조한다. 이 담당의 해당 3개 테스트 실행은 통과했다.
- 공통 head 전환은 현재 페이지의 정적 메타 노드만 캡처해 SEO 컴포넌트가 commit될 때 해제한다. 초기 본문을 제거하거나 전체 화면 로더로 가리는 변경은 없다. 테스트는 초기 메타 유지, StrictMode, SPA·noindex 전환과 실제 제목/선택 URL을 검사하며 소유권·보안·폰트/광고 리소스 보존도 확인한다.
- root가 전달한 관련 23개 테스트 통과 결과와 각 검사의 assertion을 검토했다. 이 담당이 23개 전체를 중복 실행한 것으로 기록하지 않는다. 전체 타입·빌드 결과는 root의 최종 실행 결과로 따로 확정해야 한다.

## 실제 화면과 남은 확인

- 이 담당의 브라우저 inventory는 계속 비어 있어 직접 조작·스크린샷·모바일 검증은 불가능했다. 아래 root의 공용 실제 화면/DOM·동작 자료와 직접 검토한 소스를 구분한다.
- 로컬 메타 전환·카드/검색·SPA 동작은 아래 조건에서 확인했다. 운영 배포 후 동일한 태그와 URL이 유지되는지, breadcrumb 전체·모든 필터/이미지/언어 상태가 정상인지에 대한 확대 검증은 남아 있다.
- 초기 HTML의 추천 내용이 늘어났으므로 실제 앱으로 전환할 때 높이 차이·푸터 이동·CLS가 달라지는지 확인이 필요하다. 소스상 CSS 무변경만으로 레이아웃 안정성을 보장하지 않는다.
- 기존 추천의 게임 내 타당성을 새로 검증한 것은 아니다. 이번 대조는 원본 데이터를 임의 변경하지 않았다는 검증이며, 글자 수 증가가 검색 승인이나 콘텐츠 품질 통과를 뜻하지 않는다.
- 로그인·제보 제출·운영 DB/Storage 쓰기, Notion 동기화, 타입/빌드 중복 실행, commit/push·배포는 이 담당이 하지 않았다.

## 교차 검토와 운영 자료

위 1차 판정을 고정한 후 공용 브라우저 자료와 아래 보안 교차 검토를 별도로 추가했다. 비공개 Search Console 수치·계정 정보는 이 문서에 보관하지 않는다.

### 공용 로컬 브라우저 확인 — 메타 전환·기존 동작

root는 현재 로컬 페이지에서 title·canonical·description·robots가 각각 1개이고 인증·CSP·광고 태그도 보존됨을 확인했다. 파티 6개 카드의 원래 순서, 검색 결과 없음→검색 초기화 복구, SPA 소개 페이지 이동→뒤로가기도 정상이라고 전달했다. 이 담당이 직접 조작한 것으로 표현하지 않으며, 운영 배포 후에도 동일하다는 확인을 대신하지 않는다.

### 모바일 본문 화면 밖 밀림 — 기존 운영 재현과 최소 수정

- root가 기존 운영과 수정 중인 로컬 페이지 양쪽에서 재현했다. viewport 설정 390×844, 실제 client width 382에서 H1 경계가 left 398/right 618로 화면 오른쪽 밖에 있었다. 사이드바가 모바일 가용 폭을 차지하는데 최상위 flex가 row여서 본문이 밀렸다. 데스크톱 실제 1272 폭에서는 기존 3열 카드가 표시됐다.
- 확정된 화면 접근 결함이며, 특정 검색 엔진 분류의 유일한 원인이라고 단정하지 않는다.
- 최소 수정: 최상위 컨테이너에 `flex-col lg:flex-row`만 추가했다. 모바일에서는 사이드바 위·본문 아래로 쌓고 lg 이상에서는 기존 row를 유지한다. 본문 wrapper의 `min-w-0`, 카드의 그리드·색상·간격·이미지·내용·순서는 그대로다.
- 전용 회귀 검사는 root의 mobile column/desktop row 클래스, 본문 최소 너비 처리, 원래 6개 카드의 순서를 검증한다. 추가 후 `nte-page-seo.test.tsx` 4개 테스트가 통과했다. happy-dom의 클래스 검사이므로 실제 브라우저 좌표·가독성 검증으로 확대하지 않는다.
- 후속 로컬 빌드의 실제 좌표·화면 확인 결과는 다음 절에 기록한다. 빌드는 root가 수행하며 이 담당은 중복 실행하지 않았다.

### 수정 후 공용 브라우저 확인 — 모바일 접근 복구·데스크톱 보존

root가 최종 로컬 빌드에서 다음을 직접 조작·수집해 전달했다.

- 모바일 설정 390×844, 실제 client 384×844에서 H1 경계가 left 16/right 368/top 231로 화면 안에 들어왔다. 화면에서 제목·검색·첫 파티가 보였고 DOM에 기존 6개 카드가 있었다. 수정 전 실제 client는 382였으므로 정밀한 같은 픽셀 조건의 차분 비교라고 주장하지 않는다.
- 데스크톱 설정 1440×900, 실제 client 1432×900에서 첫 3개 파티 제목의 x는 294.84/686.89/1078.77, y는 모두 550이었다. 나머지 3개는 y 1158로 다음 행에 있어 기존 3열 구성이 유지됐다. root의 inline 스크린샷 관찰도 정상이라고 전달받았다.
- 감정사·비소·설지·탄멍멍 상세 4개 URL에서 runtime title/canonical/description/robots가 각각 1개이고 인증·CSP·광고 태그도 각각 1개로 보존됐다. 파티 페이지도 title/canonical 각 1개였다. 수정 전 NTE 메타 중복 관찰과 구분한다.
- 파티 검색 결과 없음→초기화 복구, 소개 페이지 SPA 이동(`/about` canonical 1개)→뒤로가기는 root가 직접 검증했다. 모든 태그 필터·다국어·다른 기기의 검사를 대신하지 않는다.
- 제한된 error 레벨 로그 조회(limit 15)는 빈 배열이었다. 전체 세션·전체 경로 콘솔 오류가 0개라고 확대하지 않는다.
- 원본 스크린샷 파일 저장은 하지 못해 증거는 공용 DOM·조작 기록과 도구 inline 이미지 관찰이다. 이 담당의 독립 픽셀 비교나 영구 스크린샷 원본 보관 완료로 표현하지 않는다.

후속 판정: **공용 로컬 표본에서 모바일 본문 접근 복구·데스크톱 3열 보존·메타 중복 제거와 제한된 검색/탐색 동작을 확인했다.** 전체 사이트 디자인·실사용 CLS·운영 배포·색인 결과의 합격 판정은 아니다. root가 진행하는 최종 타입·전체 테스트·빌드 및 본문 누락 차단 검증은 별도 완료 조건이다.
