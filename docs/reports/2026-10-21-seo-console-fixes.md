# Search Console 점검 후 수정

## 확인과 범위

- 속성: https://riragamehub.com/. 색인 보고서 갱신 2026-10-12, 246개 색인·760개 제외. 발견됨 621, 크롤링됨 28, Soft 404 11, 대체 canonical 71, 리디렉션 21, 404 5, noindex 3.
- 사이트맵은 10월 19일 수집 성공, 890개 발견. 보고서와 수집 시점은 다르다.
- NTE 파티 URL 검사: 10월 13일 마지막 수집, 수집·색인 허용이나 Soft 404. 현재 서버 본문에는 파티 6개가 존재한다. 코드 검증을 Google 색인 해제로 보고하지 않는다.
- 기존 미커밋 AGENTS.md·다른 보고서는 보존한다. Notion 동기화·계정 설정·사이트맵 재제출은 실행하지 않는다.

## 원인과 수정

1. 홈페이지가 연결하는 `/search`가 엣지 허용 목록과 React 라우터 모두에 없어 HTTP 404 및 렌더 후 404가 발생했다. 사이트맵에는 넣지 않고 앱 허용 목록과 라우터에 추가했다. 기존 검색 모달을 재사용하고 URL의 `q` 검색어를 전달한다. 기존 noindex 정책과 미존재 URL의 404, 폐기 블로그의 410은 유지한다. `/login`·`/profile`은 실제 페이지가 아니라 모달 중심 앱이므로 공개 경로로 추가하지 않는다.
2. WW 초기 HTML이 레거시 TypeScript와 번역 템플릿을 읽어 실제 앱의 병합된 로컬 데이터와 달랐다. 앱과 같은 생성 JSON을 읽도록 변경하여 설지 스킬 9개·실제 수치·레벨 90 능력치를 대조했다. 원본 데이터는 수정하지 않았다.
3. 공통 요약의 과장·미완성 조사·정보 없는 일반론을 사실 기반 세팅 요약으로 변경했다. WW 스킬·공명 체인의 표시용 마크업 기호도 초기 텍스트에서 정리했다. 원본 콘텐츠는 보존한다.
4. WW 캐릭터 title·description을 공통 함수로 생성하여 초기 HTML과 앱 렌더 이후 차이를 방지한다.
5. 미치환 수치와 공통 생성 문구에 대한 WW 캐릭터 감사, 실제 앱 경로 통과 회귀 검사를 추가했다. 기존 NTE 4인 파티 초기 HTML 감사는 유지한다.
6. 운영 검색 결과를 실제 선택하니 WW 캐릭터·세팅 공략이 Notion UUID로 이동하는 기존 문제가 재현됐다. WW 검색의 경로 ID를 앱의 경량 캐릭터 목록에 있는 정규 ID로 고정하고, 이름으로 부가 설명만 병합한다. 설지는 `baizhi`로 연결되어야 한다는 실제 자료 기반 회귀 검사와 전체 검색 ID 검사를 추가했다.
   - 정규 상세 페이지가 없는 로컬 UUID 기록 4개(쇄명·여우의 별자리·경연·청초)는 새 상세 URL을 추측해 만들지 않는다. 캐릭터 메뉴의 검색 결과로 연결하고, 존재하지 않는 상세 공략 링크는 생성하지 않는다. 원본 데이터는 삭제하지 않는다.

## 검증

- 최초 관련 검사: 7개 실패(앱 경로 4건·초기 콘텐츠 검사 3건). 실제 앱 라우터와 맞춰 검색 경로 2건 및 초기 콘텐츠 3건으로 회귀 범위를 정리했다. 직접 검색 진입·검색어 전달·noindex·닫기/재열기 검사도 추가했다.
- TypeScript 통과. 전체 build 통과. 사이트맵 890개 전부 초기 HTML SEO 감사 통과. 성능 예산 통과.
- 1차 전체 테스트: 샌드박스 임시 파일 ENOENT 후 외부 환경 재실행으로 64개 파일·436개 테스트 통과. 이후 실제 화면에서 찾은 검색 라우터 누락 수정 후 최종 타입·빌드·SEO·성능 감사와 65개 파일·435개 테스트를 다시 통과했다(실제 경로가 아닌 로그인·프로필 2건 제거, 검색 페이지 1건 추가).
- 생성된 설지 초기 HTML의 제목·설명을 공통 생성 결과와 비교하고 스킬 9개 이름을 대조했다.
- 성능 예산은 로컬 압축 추정치이며 운영 Core Web Vitals 측정이 아니다. UI 구조·권한·보안 헤더는 변경하지 않았다.
- 브라우저의 로컬 프리뷰 접속은 타임아웃으로 미검증. 운영 배포 확인으로 별도 대조해야 한다.
- 첫 커밋 99ce32c의 CI·보안 audit·Cloudflare 성공과 운영 HTTP 응답을 확인했다. 브라우저에서는 React 검색 경로 누락이 발견되어 후속 수정했다. HTTP 200만으로 화면 검증을 대체하지 않는다.
- 후속 1b95216도 CI·보안 audit·Cloudflare 성공. 운영 검색창과 설지 결과 표시를 확인했으나, 결과 클릭에서 기존 UUID 링크 오류를 발견해 마지막 경로 보정으로 해결했다. 경로 보정 후 타입·build·890개 SEO 감사·성능 예산과 66개 파일·436개 테스트를 모두 재통과했다.

## 남은 외부 처리

- Google 재크롤링·색인 및 유효성 검사 결과는 대기 사항이다. 발견됨 621개를 개별 오류로 단정하거나 대량 색인 요청하지 않는다.
- 데이터 자체의 사실 정확성 전체 재검수는 이번 SEO 구현 수정과 다르다. 생성기가 원본에 없는 수치를 추측해 추가하지 않는다.
- CI·Cloudflare·운영 확인 결과는 완료 보고에서 구분한다.
