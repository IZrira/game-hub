# 콘텐츠 관리자 정책 성능·무결성 검토

2026-10-16 · 범위: `20261016141014_restrict_content_writes_and_internal_function.sql` · 독립 성능 역할 검토.

## 직접 확인한 정적 근거

- 공개 characters·notices·tier_lists 조회와 관리자 upsert 호출을 소스에서 대조했다. 후보는 별도 SELECT 정책·테이블 GRANT·기존 행을 변경하지 않으며, 관리자 INSERT와 UPDATE의 USING/WITH CHECK를 제공한다.
- 정책의 auth 함수는 SELECT 서브쿼리로 평가한다. 전체 테이블 재작성·신규 인덱스·집계 trigger 변경은 없다.
- 기존 event-trigger 함수의 정의·소유자·search_path·연결을 변경하지 않고, 이미 유효한 service_role 실행권한만 보존한다.
- 단일 트랜잭션, lock_timeout 2초, statement_timeout 15초로 잠금 대기를 제한한다. 소스상 새로운 무결성·성능 차단점은 발견하지 못했다.
- 소스 계약 테스트는 구조 회귀 검사이지 실제 DB 권한 검증이 아니다.

## 주 담당이 전달한 운영 검증

아래 결과는 이 검토자가 운영 DB에서 독립 실행한 실측이 아니라 주 담당의 적용 후 재조회 결과다.

- 사용자 승인 후 운영 반영. 기존 SELECT 정책 6개, GRANT와 RLS 상태는 동일하며 관리자 쓰기 정책은 9개다. 기존 두 관리자 계정의 권한 준비 상태를 확인했다.
- event-trigger 함수 정의·소유자·search_path·연결이 동일하다. anon/authenticated 실행권한은 거부되고 기존 service_role 실행권한은 유지된다.
- Advisor 항목은 12개에서 4개로 감소했고 오류는 0개다. 남은 항목이 있으므로 전체 보안 통과로 해석하지 않는다.
- rollback clone 검사 90개, 웹 테스트 364개 및 빌드는 주 담당이 실행했다.

## 성능 → UX 교차 검토

공개 조회를 줄이거나 콘텐츠를 숨겨 성능 점수를 높이는 변경이 아니다. 공개 공지·티어표·캐릭터 조회를 보존하고 기존 관리자 편집 경로의 서버 권한을 제한하는 범위로 판단한다. 실제 로그인 관리자 저장·업로드 성공, 일반 사용자 거부 UX는 카탈로그 조회만으로 입증되지 않으므로 미검증으로 유지한다.

## 판정과 한계

제한된 SQL 정적 성능·호환 검토는 통과다. 운영 부하, 쿼리 지연·실행계획, 실제 사용자 저장 여정, 새 브라우저 성능 지표는 측정하지 않았으며 기존 동시성 집계 문제도 이 변경으로 해결됐다고 주장하지 않는다. 이 검토자는 보고서 외 파일·운영 DB·브라우저를 변경하지 않았다. Notion 동기화는 실행하지 않았다.
