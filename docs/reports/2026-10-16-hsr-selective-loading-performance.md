# HSR 상세 선택 로딩 변경 검증

- 범위: 2026-10-16 기존 dirty 작업을 보존한 HSR 상세와 지연 장비/시너지 의존 분리. 구현 담당 `/root/improve_performance`의 자체 검토이며 독립 성능 평가를 대신하지 않는다.
- 원본 캐릭터·공략·장비·파티 데이터는 수정하지 않았다. Notion 동기화, commit, push, 배포는 실행하지 않았다. 전체 production build와 SEO/성능 예산 감사는 주 담당의 통합 검증 대상이다.

## 변경과 보존

기존 `CharacterDetail → gameData → HSR_DATA_ALL`은 전체 캐릭터 93개와 공략·장비 원본을 정적으로 참조했다. 캐릭터별 해시 JSON 생성과 선택 fetch로 변경했다. 기존 영문 전용 Ashveil/Castorice 두 원본, 나머지 영문 이름·속성·경로·재료 변환을 유지한다. 상세 렌더링은 데이터 로딩과 분리하여 캐릭터 이동 시 이전 응답을 숨기고 요청을 중단하며 오류 재시도를 제공한다.

지연 로딩되는 `HsrEntityGraphSection → common/data/games → HSR_DATA_ALL` 우회 의존도 제거했다. 기존 캐릭터별 공략 JSON에서 선택한 장비만 읽고 광추 등급·유물 2/4세트 효과·장신구 효과를 추가 보존한다. 가이드 전문과 전체 변형·대체 장비 데이터는 그대로다. `SynergyDeck → synergyManager → 전체 HSR 가이드`는 기존 역할과 추천 멤버를 그대로 추출한 요약 JSON으로 분리했다. 파티·대체 멤버 계산 알고리즘은 바꾸지 않았다.

생성은 기존 로컬 `generate:search-data`(build 경로), predev/pretest에 연결한다. Notion 호출을 추가하지 않았다. 해시 캐릭터 JSON은 다른 런타임 JSON과 같이 gitignore 대상이며 manifest/요약은 저장소에 유지한다.

## 정적 바이트 측정

2026-10-16 로컬 Node zlib gzip 추정이다. CDN 전송량·렌더링 시간 또는 전후 production 번들 실측이 아니다.

| 현재 선택 자원 | 비압축 bytes | 로컬 gzip bytes |
|---|---:|---:|
| 비소 상세 JSON | 9,432 | 3,031 |
| Ashveil 상세 JSON(영문 대체 포함) | 17,265 | 5,471 |
| Castorice 상세 JSON(영문 대체 포함) | 28,496 | 8,104 |
| 비소 공략/선택 장비 JSON | 9,884 | 3,127 |
| 전체 캐릭터 관련 추천용 요약 | 12,732 | 2,162 |
| 전체 캐릭터 URL manifest | 6,699 | 1,746 |
| 시너지 역할/추천 멤버 요약 | 12,718 | 2,129 |

93개 상세 JSON의 합은 849,475 bytes, 최대 개별 파일은 28,496 bytes이다. 이는 선택 로딩 자원 구성의 증거다. 기존 전체 JS 번들 크기와 같은 형식의 전후 수치가 아니므로 합계 대비 선택 자원 감소를 페이지 가속률로 표현하지 않는다. 변경 후 캐릭터별 공략 JSON 최대는 32,376 bytes로 기존 40,000 bytes 예산 내다. 예산을 상향하지 않았다.

## 확인한 범위

- 타입 검사: `npm run typecheck` 성공.
- 타깃 회귀: `hsr-character-runtime.test.tsx`, `hsr-guide-runtime.test.ts`, `m2_synergy_stress.test.ts` 3파일 21개 성공.
- 93개 상세/영문 대체의 원본 전체 객체, 추천 캐릭터 순서, 시너지 요약의 역할·추천 멤버·설명, 선택 장비 등급/효과를 원본과 대조했다.
- TypeScript AST로 상세에서 시작하는 로컬 정적 import·export·동적 import를 전이 추적했다. 모달·시너지·장비 지연 섹션을 포함해 전체 HSR gameData/index/characters/공략/장비 원본 유입이 없는 회귀 검사 성공. 네트워크 요청 목록이나 Vite 최종 chunk 그래프의 직접 실측을 대신하지 않는다.
- fetch 실패/잘못된 응답/재시도/다른 캐릭터 이동/늦은 응답 무시/요청 중단/없는 경로 무요청 검사 성공.
- 기본 Windows sandbox TEMP에서 Vitest client 파일 ENOENT가 서로 다른 모듈에서 발생했다. 프로젝트 `.cache/vitest-temp`를 해당 명령의 TEMP/TMP로 지정한 재실행은 성공했다.
- `git diff --check` 성공, 변경 diff와 신규 파일 내용 재검토. Git fsmonitor IPC 메시지와 CRLF 변환 경고가 있으나 whitespace 오류는 없다.

## 한계

구현 담당의 자체 검토다. 모바일/desktop 실제 화면, 네트워크 콜드·웜·SPA 전송량, 광고 조건, FCP/LCP/CLS/TBT/INP는 미측정이다. 이전 평가 PSI 429를 성공 수치로 대체하지 않았다. 전체 build·예산·SEO 결과는 주 담당 통합 실행 결과를 따른다. 새로운 네트워크 의존의 오류/재시도는 자동 테스트로 확인했으나 운영 CDN 오류 및 전체 화면 보존은 브라우저 확인이 필요하다.

## 주 담당 통합 검증 공유 및 성능 → 디자인 교차 검토

2026-10-16 주 담당 `/root`가 공유한 통합 결과: 355개 테스트, 타입 검사, production build, 890개 경로 SEO 검사 성공. gzip 예산 실측 공유값은 entry 24,823 / initial JS 139,377 / CSS 26,946 / 최대 chunk 206,386 bytes다. 생성 캐릭터 93개, 최대 상세 JSON 28,496 bytes도 공유받았다. 주 담당은 기존 예산을 상향하지 않고 characterRaw 40,000 bytes 검사를 신설하여 최종 재검증할 예정이다. 이 문단의 숫자는 이 담당이 직접 실행한 최종 build 수치가 아니라 주 담당 전달 증거이며, 후속 최종 결과로 대체 확인해야 한다.

주 담당의 제한된 로컬 브라우저 표본 공유: HSR 비소의 광추 4개·유물 2개·장신구 3개·추천 파티 3개 텍스트 표시 정상, 해당 탭 error 관측 빈 목록. 이 담당이 화면을 직접 확인한 것은 아니며 전체 캐릭터·기기·상태의 보존이나 운영 CDN 전송 성공으로 확대하지 않는다.

디자인 담당의 `2026-10-16-improve-design-code-review.md`와 실제 GlobalSearch/SearchModal/Navbar/useDialogFocus, Aniimo Gallery, WW CharacterDetail 변경 diff를 읽었다. 검색은 원래 결과·데이터 요청·광고·화면 콘텐츠를 제거하지 않고 포커스 이벤트 처리와 대화상자 의미를 추가한다. 이벤트 리스너는 해제하며 프레임 반복 작업을 추가하지 않는다. Aniimo는 무결과 상태에 필터 초기화 버튼만 추가하여 원래 카드가 다시 표시되게 한다. 기존 카드·이미지·비교 기능을 숨기거나 줄이지 않는다. Navbar는 복귀 대상 속성만 추가한다.

WW 속성 아이콘은 검증된 파일명으로 수정하고 실패한 장식 이미지에 한해 숨기는 fallback을 둔다. 속성·무기 텍스트는 유지한다. 이 제한적 오류 fallback은 해당 이미지가 실제로 표시됐다는 증거가 아니며 디자인 담당도 그 한계를 적었다. 정상 콘텐츠·광고·이미지를 감춰 성능 수치만 올리는 변경으로 판단할 근거는 없다. 실제 각 속성 이미지와 검색 키보드 동작의 브라우저 결과는 주 담당 검사 또는 후속 표본을 따른다.

교차 결론: 확인한 코드 범위에서 디자인 수정과 HSR 선택 로딩은 콘텐츠·광고를 제거하는 방식으로 성능을 개선하지 않는다. 디자인 담당의 실제 viewport·스크린리더·픽셀·전체 접근성 미검증 판정을 정적 의존 분리나 초기 자산 예산 성공으로 상쇄하지 않는다. 이견 없음.
