## 1. 결론

사이트 전체가 robots.txt나 noindex에 막힌 상태는 아니다. 주요 페이지는 검색용 초기 HTML, 개별 제목, canonical, 본문과 내부 링크를 제공한다. 현재 가장 큰 과제는 **Google의 발견 후 미크롤링 대기 621개와 Soft 404 11개의 후속 확인**, 그리고 **초기 HTML과 실제 화면의 일관성**이다.

사이트맵을 다시 제출하거나 페이지 수를 늘리는 것만으로 해결할 단계는 아니다. 이미 Google이 사이트맵을 성공적으로 읽고 890개 URL을 발견했다. 중요한 페이지부터 실제 검색 의도에 맞게 보강하고, 최신 크롤링 결과를 확인하는 접근이 필요하다.

이번 점검으로 검색 순위, 색인 또는 AdSense 승인을 보장할 수 없다. 근거 없는 종합 점수도 부여하지 않는다.

## 4. 기술 SEO 확인 결과

### 통과 또는 정상으로 확인한 항목

- `/robots.txt`는 HTTP 200이며 전체 허용 상태다. scratch, _company, supabase 경로만 차단한다. 사이트맵 위치도 올바르다.
- 사이트맵 색인과 하위 6개 XML이 모두 HTTP 200으로 응답했다.
- 890개 URL은 중복이 없고 모두 `https://riragamehub.com/` 호스트다.
- HSR 405개, WW 264개, NTE 100개, Aniimo 107개, 공통 9개, 공지 5개로 구성된다.
- 별도 분석 가이드 32개도 각 게임 사이트맵에 포함된다. 공지 사이트맵이 5개라는 이유로 분석 가이드가 빠진 것은 아니다.
- 확인한 공개 페이지 24개는 HTTP 200, 개별 제목·description·canonical·H1·초기 본문을 제공했다. index 금지 메타 및 X-Robots-Tag는 표본에서 발견하지 않았다.
- `?lng=en`, `?lng=ko` 예시는 쿼리를 제거한 주소를 canonical로 가리켰다. 소스 HTML은 한국어였으므로 완전한 영문 SEO 지원으로 간주하지 않는다.
- 존재하지 않는 `/seo-audit-nonexistent-20261017`은 **HTTP 404**, 오류 제목, meta와 응답 헤더의 noindex를 반환했다. 모든 없는 경로가 홈 HTML+200으로 떨어지는 상태는 표본에서 재현되지 않았다.
- `/admin`은 noindex, nofollow다. 관리자 페이지 제외를 없애는 방향은 권장하지 않는다.
- `/ads.txt`는 200이고 Google 게시자 레코드가 있다. 이는 AdSense 승인 또는 콘텐츠 품질 증명이 아니다.

### 초기 HTML과 실제 화면의 차이 — 개선 필요

NTE 파티:

- 초기 제목: `이환 추천 파티 | 4인 속성·에스퍼 사이클 조합 | RIRA ARCHIVE`
- 최종 제목: `이환(NTE) 추천 파티 조합 및 4인 속성 시너지 가이드 | RIRA ARCHIVE`
- 초기 H1: `이환 4인 추천 파티 조합`
- 최종 H1: `4-SLOT ESPER COMBINATIONS`
- canonical은 초기·최종 모두 `/gallery/nte/parties`로 유지됐다.

WW 갈브레나:

- 초기 H1: `명조 갈브레나 상세 정보 & 종결 육성 가이드`
- 최종 H1: `갈브레나`
- 초기 검색용 텍스트 약 7,119자, 최종 화면 전체 텍스트 약 3,536자로 추출됐다. 추출 범위가 다르므로 차이를 곧바로 누락 분량으로 해석하지 않는다.
- 최종 관찰 시 LOADING ARCHIVE 문구는 사라졌고, 당시 완료된 이미지 중 깨진 이미지는 0개였다. 전체 이미지 자산 보장은 아니다.

HSR 피해 공식 분석 가이드:

- 초기·최종 H1 모두 `스타레일 피해 공식과 계수 계산 가이드`로 확인됐다.
- 초기 본문 약 6,096자, 최종 화면에 방어 관련 설명을 포함한 가이드 본문이 표시됐다.

NTE·WW에서는 첫 관찰 시 공통 헤더·푸터와 LOADING ARCHIVE만 보였다가 실제 본문이 나타났다. 이 관찰만으로 정확한 지연 시간이나 Google의 Soft 404 원인을 확정할 수 없다. 다만 검색용 본문이 앱 전환 중 비고 최종 본문을 기다리는 구간은 추가 계측할 가치가 있다.

권장: 제목·description·H1·주요 설명을 동일한 데이터 원본에서 만들고, 초기 콘텐츠가 실제 화면에도 자연스럽게 이어지도록 한다. 같은 의미의 표현 차이는 곧바로 SEO 오류가 아니지만, 한국어 페이지의 최종 H1을 영어만으로 바꾸는 등 불필요한 편차는 줄이는 편이 좋다.

### lastmod의 신뢰도 — 설계 위험 확인

`scripts/generate-sitemap.js`의 `getFileLastmod()`는 파일 시스템 `mtime`을 사용한다. 분석 가이드는 `reviewedAt` 또는 `publishedAt`을 쓰는 경로도 있다.

mtime은 체크아웃·파일 재생성으로도 바뀔 수 있어 콘텐츠의 실제 의미 있는 수정일과 달라질 위험이 있다. 이번 점검에서 모든 운영 lastmod가 잘못되었다고 입증한 것은 아니다.

권장: 콘텐츠별 수정일 또는 실제 콘텐츠 변경 커밋 날짜를 우선 사용하고, 메타데이터만 바뀐 배포로 모든 콘텐츠 날짜가 갱신되지 않는 회귀 검사를 추가한다. 사이트맵의 lastmod는 실제 중요한 변경과 일치해야 한다. [Google 사이트맵 안내](https://developers.google.com/search/docs/crawling-indexing/sitemaps/build-sitemap)

다음 확인 절차:

1. NTE 파티와 무기 2개를 먼저 URL 검사에서 확인한다.
2. Google 저장 HTML·스크린샷과 현재 실시간 렌더링을 비교한다.
3. 최종 본문이 비거나 오류·준비 중 상태가 노출되는지 확인한다.
4. 언어 쿼리는 canonical 대상 페이지와 함께 검사한다.
5. 현재 문제 수정과 검증이 끝났을 때만 유효성 재검사 또는 중요 URL 색인 요청을 진행한다. 이번에는 요청하지 않았다.

HTTP 200은 색인을 보장하지 않으며, 오류처럼 보이거나 빈 내용이면 Soft 404로 처리될 수 있다. [Google HTTP 상태 설명](https://developers.google.com/crawling/docs/troubleshooting/http-status-codes)

- 얇은 본문 표본: 공지 376~407자, NTE 에드가·파디아 가이드 각 517자, 치즈 546자, 우미츠키 548자, 아들러 550자.

이 검사는 프로젝트 자체 기준 통과다. Google 품질 판정이나 구조화 데이터 리치 결과 인증은 아니다. 공지의 짧은 길이는 목적에 맞으면 정상이다. NTE 육성 공략은 실제 선택 기준·운용·대안이 충분한지 사람이 검토할 우선 후보로 삼는다.

구조화 데이터는 운영 표본의 일부 허브·공략에서 존재하고 일부 상세·분석 글에서는 없었다. 모든 페이지에 JSON-LD가 필수는 아니다. Rich Results Test와 Google 선택 canonical의 전수 확인은 미수행이므로 별도 검증 대상으로 남긴다.

## 7. 개선 우선순위

### 1순위: Soft 404 현재 상태와 렌더링 일관성 확인

대상: NTE 파티 → WW 무기 2개 → 나머지 8개.

이유: 실제 검색 제외 및 검사 실패가 확인됐다. 현재 200 응답만 보고 해결 처리하면 안 된다.

완료 기준: 저장된 Google 화면과 현재 화면의 차이가 설명되고, 중요한 본문이 오류·빈 화면 없이 렌더링되며 제목·H1·canonical 회귀 검사를 통과한다. Google의 최종 해제는 별도로 기다린다.

### 2순위: 발견됨 621개·크롤링됨 미색인 28개의 중요도별 선별

621개를 한 번에 요청하거나 전부 장문으로 늘리지 않는다. 인기 캐릭터, 실제 유입 검색어, 최근 변경, 완성된 분석 가이드 중 10~20개를 먼저 선별한다.

허브 → 캐릭터 → 세팅/분석 → 장비/파티가 실제 관련 링크로 연결되도록 검토한다. 현재 허브 링크 수는 충분히 존재하므로 무작정 링크를 더 늘리기보다 중요 문서의 문맥과 깊이를 개선한다.

완료 기준: 선별 URL별 현재 상태·마지막 크롤링·본문 변경일을 기록하고, 다음 보고서에서 새 크롤링 및 색인 전환을 비교한다. 날짜만 갱신하는 작업은 하지 않는다.

### 3순위: HSR·WW·NTE의 검색 질문별 자체 분석 강화

애니모 지역 페이지의 성과를 참고하되 내용 자체를 복제하지 않는다.

- HSR: 속도 컷 선택, 광추 대안의 손실, 특정 조합의 행동 순서.
- WW: 무기 선택 조건, 에코 운용, 캐릭터별 실제 파티 교대 순서.
- NTE: 콘솔 배치, 카트리지 선택, 기본·복합 사이클의 실제 적용 조건.

각 글은 간단한 결론 → 선택 기준 → 짧은 실전 예시 → 주의사항으로 정리한다. 이미 있는 세팅표와 같은 설명을 반복하지 않는다. 기계적으로 생성한 긴 공통 문구보다 검증된 차별 정보를 우선한다.

### 4순위: lastmod와 언어 URL 정책 정리

mtime 의존도를 줄이고, 초기 HTML과 최종 화면의 언어·canonical 정책을 문서화한다. 영어 페이지가 실제 독립 콘텐츠로 완성되지 않았다면 `?lng=en`을 영어 검색 지원 완료로 홍보하지 않는다.

canonical은 강제 명령이 아니라 신호다. 내부 링크·사이트맵·리디렉션에서 상충하는 주소를 만들지 않도록 검증한다. [Google canonical 안내](https://developers.google.com/search/docs/crawling-indexing/consolidate-duplicate-urls)

### 5순위: 정기 재측정

수동 실행 시 같은 URL 표본과 지표를 비교한다. 자동 예약은 설정하지 않는다.

- 사이트맵 수와 중복, HTTP 상태, robots/noindex/canonical.
- 초기 HTML·최종 화면의 title/H1/본문 의미 일치.
- Search Console 집계일, 색인 수, Soft 404, 중요 URL별 마지막 크롤링.
- 검색 실적의 실제 기간과 허브별 클릭·노출 변화.
- 모바일·데스크톱 실측 성능과, 데이터가 생겼을 때의 CrUX.
