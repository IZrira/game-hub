# 상세 페이지 스크롤 작업량 개선

2026-11-01 KST. 기준 commit e28bee3. 아하 스킬 아래 스크롤 지연 신고에 대한 변경 범위 검토다.

## 확인한 비용과 변경

- DetailStickyNav는 스크롤 이벤트마다 각 섹션의 offsetTop을 읽고 같은 활성 값도 상태 setter에 전달했다.
- 두 섹션·20번 스크롤 회귀 테스트를 먼저 실행해 섹션마다 20번, 총 40번 위치 읽기를 재현했다. 변경 후 scroll 경로의 offsetTop/getBoundingClientRect 읽기는 0번이다. 활성 섹션이 달라질 때만 상태를 갱신한다.
- 섹션 위치는 최초 진입, 창 크기 변경, body/섹션의 ResizeObserver 알림에서 갱신한다. 성혼 펼침 등 높이 변경에 따른 위치 이동을 반영한다. 관찰자·리스너를 해제하며, ResizeObserver 미지원 환경에서는 기존처럼 실시간으로 위치를 측정해 기능을 보존한다.
- HSR 스킬·추가 능력·성혼 카드에만 중복 backdrop blur를 해제했다. 카드 배경색·그림자·크기·간격·본문·툴팁·토글·SEO는 유지한다. 공통 고정 메뉴의 시각 효과는 변경하지 않았다.
- 최초 CSS 선언 순서에서 최적화기가 접두어 선언만 남겨 실제 blur 해제가 적용되지 않았다. 브라우저 computed style 검사로 발견하고 접두어→표준 순서로 수정했다. 최종 빌드의 10개 해당 카드 모두 backdrop-filter: none을 확인했다.

## 성능 측정 한계

- 운영 과부하 없이 로컬 production preview에서 아하 스킬 구간을 스크롤했다. 한국어·로그아웃·1440×900 iframe, 기본 일반 공격 탭·E2 접힘, 16px씩 300 프레임, 3회 requestAnimationFrame 간격을 수집했다. CPU/네트워크 제한은 미적용, HTTP 콜드 캐시는 미확인이다.
- 기준 실행 3회의 p95 간격은 각각 약 4.3ms였고 25ms 초과는 없었다. 중간 실행은 약 16.8ms로 프레임 콜백 주기가 달랐다. 이 환경 차이를 통제하지 못했으므로 전후 FPS 개선율을 계산하지 않는다.
- 사용자 기기의 프레임 드랍을 같은 수준으로 재현하지 못했다. DOM 위치 읽기 제거·실제 blur 해제는 확인했지만 체감 개선, GPU 시간, 실제 사용자 INP 또는 모든 지연 해결을 확정하지 않는다.
- 최종 실행은 p95 약 16.8ms씩 3회, 최대 간격 50.1/21.4/21.1ms, 25ms 초과 2/0/0회, 50ms 초과 1/0/0회였다. 기준과 콜백 주기가 달라 동일 조건 A/B 결과로 사용하지 않는다.
- 임시 측정 페이지는 dist와 .cache에서만 사용하며 저장소/배포에 포함하지 않는다.

## 검증 및 독립 검토

- TypeScript, production build, 빌드 내 SEO·성능 예산 감사 통과. 전체 78개 파일·600개 테스트 통과.
- 회귀 검사: 스크롤 중 위치 읽기 없음, 동적 높이 변경 후 활성 섹션 재계산, ResizeObserver 미지원 대체 동작. 기존 8명 E2 원문 대조와 토글 검사 유지.
- 실제 브라우저: HSR 행적·스킬 이동, E2 펼침, WW 백지 공명 체인 이동, NTE 감정사 콘솔 배치 이동과 활성 강조 확인. HSR 카드 computed style과 실제 화면을 직접 확인했다.
- 390×844 모바일에서도 가로 넘침 없음, 6개 성혼 제목 한 줄 전체 표시, 모든 해당 카드 blur 해제, Enter 토글 닫기 확인.
- 성능 담당 독립 에이전트: 캐시된 숫자 비교·동일 값 상태 갱신 생략·관찰자 정리 확인. 미지원 브라우저 제한 지적은 fallback으로 반영했다.
- 보안 담당 독립 에이전트: 인증·권한·요청·로그·SEO·원본 콘텐츠 변경 없음, 메모리 내 위치 데이터만 사용. 차단 사항 없음.
- 디자인 담당 독립 에이전트: 카드 배치와 접근성 유지, 공통 메뉴의 WW/NTE 확인 권고를 실제 화면 검사에 반영. 정적 검토로 체감 개선을 확정하지 않았다.
