## 측정 증거

측정 방법은 Node `fs`의 파일 바이트 수와 `node:zlib`의 `gzipSync`다. 이전 값은 `git show HEAD:<path>`로 읽었다. gzip은 로컬 추정이며 실제 CDN 전송량이 아니다.

- 캐릭터 목록 요약: 19,098 → 19,324 raw bytes, 2,523 → 2,556 gzip bytes. 증가량은 raw 226 / gzip 33 bytes.
- 상세 탐색용 요약: 12,732 → 12,891 raw bytes, 2,162 → 2,189 gzip bytes. 증가량은 raw 159 / gzip 27 bytes.
- 상세 manifest: 6,699 → 6,771 raw bytes, 1,746 → 1,765 gzip bytes. 증가량은 raw 72 / gzip 19 bytes.
- 신규 상세 `public/assets/data/hsr/characters/aeon_aha.09588b66807a.json`: 16,789 raw / 5,041 gzip bytes. 고정 상세 예산 40,000 raw bytes보다 작다.
- 이전 manifest 93개 중 변경된 기존 경로는 0개이며 추가 키는 `aeon_aha` 하나다. 현재 94개 상세 JSON이 생성되었다.
- 공략 버튼 조건 확인에 새로 참조하는 공략 manifest는 6,327 raw / 1,737 gzip bytes다. 공략 본문 전체를 정적 import하는 변경이 아니다.

## PASS — 로딩·의존성·표시 정책

1. `CharacterDetail.tsx`는 기존 `useHsrRuntime`으로 선택된 캐릭터의 해시 JSON URL 하나를 요청한다. `AbortController`, 응답 ID 검증, 이전 응답 노출 방지가 유지된다.
2. 상세 화면·장비 지연 영역·팝업을 통한 전체 HSR 원본 DB의 클라이언트 전이 import를 기존 회귀 테스트로 확인했다. 새 캐릭터 원본은 작성·생성용이며 상세 정적 의존에 직접 들어가지 않는다.
3. 전용 효과는 새 그룹에 있는 캐릭터에게만 탭을 표시한다. 아이콘이 제공되지 않은 경우 존재하지 않는 파일 URL을 만들지 않는다. 나머지 캐릭터의 그룹 분류·스킬 배열·성혼 배열을 줄이는 변경이 없다.
4. 등록 공략이 없는 새 캐릭터는 공략 버튼을 노출하지 않는다. 기존 공략은 가벼운 manifest 등록 여부로 유지하며 공략 전체 본문을 로드하지 않는다.
5. 기존 목록·스킬·성혼의 지연 이미지 정책과 영역 크기는 유지된다. 전체 이미지 preload, 인증·캐시·CSP 완화, 광고 제거 또는 성능 예산 상향을 발견하지 못했다.
