# 변경 범위 성능 검토 — NTE SEO·파티 초기 HTML

## 범위와 독립성 한계

- 기준: PERFORMANCE.md, THREE_ENGINEER_REVIEW.md 1.0. 기준 HEAD `6d451bfa61c0b92b31c4e4465f6ea91b630ea898` 이후 현재 작업 diff를 검토했다.
- 성능 담당 1차 판정 고정: 2026-10-16 03:18:02 UTC / 12:18:02 KST. 이 판정까지 다른 담당의 결론은 열람하지 않았다.
- 파티 초기 HTML helper는 이 담당이 구현했다. 자기 구현 검토이므로 완전히 독립적인 코드 리뷰라고 주장하지 않는다. root의 별도 검토·전체 검증과 보안/디자인 교차 확인이 필요하다.
- 대상: 공통 SEO/head 전환, JSON-LD 직렬화, `/gallery/nte/parties` 초기 본문. 전체 사이트 성능 재평가가 아니며 비공개 Search Console 수치는 포함하지 않는다.
- 기존 AGENTS.md 및 다른 담당·사용자 변경을 보존했다. Notion·운영 DB·인증·광고 설정·예산·사이트맵 정책을 변경하지 않았다.

## 확인한 구조

- `capturePrerenderSeoHead`는 모듈 초기화 시 head.children을 한 번 읽고 정적 페이지 메타데이터 노드 참조만 보관한다. 첫 SEO commit에서 그 노드만 제거하며 매 프레임 polling이나 매 탐색마다 전체 문서 검색을 추가하지 않는다.
- 제거 대상은 title, canonical, 페이지 설명/robots/OG/Twitter/article 메타, JSON-LD다. 초기 본문·스타일·폰트·preload·modulepreload·광고 스크립트·CSP·소유권 인증 태그는 대상이 아니다. 이후 생성된 React 메타데이터도 캡처 참조에 없으므로 제거하지 않는다.
- `LiveSeoHead`의 useLayoutEffect와 ready state는 마운트당 한 번 추가 commit을 만든다. 이는 paint 전의 유한한 작업이며 실제 비용·LCP/CLS 영향은 아직 측정하지 않았다. 이 변경만으로 기존 비홈 로딩 레이아웃 이동 문제가 해결됐다고 보지 않는다.
- JSON-LD는 기존 JSON.stringify 결과에 `<`, U+2028/U+2029 escape를 적용한다. 원래 데이터나 광고 로더를 제거하는 방식이 아니며, 빌드·런타임 모두 동일한 안전한 직렬화를 사용한다.
- NTE 파티는 로컬 TS의 `NTE_PARTY_COMBINATIONS` 리터럴만 빌드에서 추출한다. import·동적 fallback·임의 코드를 실행하지 않는다. TypeScript AST와 원본 전체 모듈을 런타임 도감/공략 의존으로 추가하지 않았다.
- 생성 대상은 기존 로컬 6파티, 멤버 24자리, 대체 멤버 18자리다. 설명·역할·속성·분류·태그·장단점과 순서를 보존한다. 알려진 사이트맵 캐릭터명 경로 48개만 연결하며 미등록 대상은 텍스트로 남긴다.
- 본인 구현은 다른 feature 초기 본문, 런타임 파티 UI·원본 데이터, 초기 본문 마운트 정책을 변경하지 않았다. 이후 공용 실제 화면 검사에서 발견한 기존 모바일 배치 결함의 최소 수정은 아래 별도 교차 검토에 기록한다. 파티 초기 본문이 캐시/원격 관리자 데이터의 모든 상태까지 동일하다는 뜻은 아니다.

## 용량과 검증 근거

- helper 단독 출력: UTF-8 raw **10,168 bytes**, Node gzip 추정 **1,642 bytes**. 로컬 6파티와 현재 `sitemap-nte.xml`을 넣어 계산한 HTML fragment이며 전체 HTML·운영 CDN 전송량이 아니다.
- 빌드 전용 AST parser 추가로 런타임 JS·CSS에 compiler/전체 파티 DB가 추가되지 않는 구조임을 import 경계에서 확인했다. root의 모바일 최소 수정 후 공용 build에서도 entry gzip 24,158/32,000 bytes, 초기 JS gzip 138,712/170,000 bytes, CSS gzip 26,898/34,000 bytes, 최대 chunk gzip 206,386/250,000 bytes로 예산을 통과했다. 모두 로컬 gzip 추정이며 운영 CDN 전송량이 아니다. 기존 entry 24,159/초기 JS 138,713 대비 각각 1 byte 차이이므로 유의미한 페이지 가속으로 표현하지 않는다.
- 이 담당의 타입 검사 통과, 전용 테스트 **11개 통과**. 원본 TS 추출 deepEqual, 파티/멤버/역할/설명/대체 및 태그·장단점의 순서, 내부 링크 allowlist, HTML escape·경로 이탈 거부, 임의 표현식 거부를 확인했다.
- `git diff --check` 오류 없음. 기존 변경에 LF/CRLF 안내는 있다.
- root 공용 실행 근거: 모바일 최소 수정 후 타입·validate:data·전체 테스트·production build·성능 예산 통과를 전달받았다. 최신 SEO 감사는 사이트맵 890 URL/정적 HTML 985개, 일반 가이드 32개 최소 376자다. 파티 최종 article은 1,886자/6파티/24멤버/18대체/48링크로 대조됐다. 이 담당이 전체 명령·화면 검사를 중복 실행한 것으로 기록하지 않는다.
- validate:data의 기존 키레네 혼합 속도 2세트 참조 경고 2건과 오래된 production_artifacts의 931 route 요약은 최신 SEO 890/985와 구분한다. 마지막 파티 본문 누락/4인 누락 guard 및 유지 MD 추가 후 root가 전체 검증을 다시 실행 중이므로 그 최종 회차는 아직 대기다.

## 판정과 남은 검증

판정: **변경 범위 소스 검토에서 성능 차단점은 발견하지 못했고, 전달받은 공용 빌드/예산 검증은 PASS다. 마지막 guard 추가 후 최종 검증 회차는 대기, 실제 성능은 UNVERIFIED다.** 콘텐츠·광고·보안 보호를 숨기거나 줄여 점수를 높인 변경은 없다.

완료 전 root가 확인할 항목:

- 마지막 guard와 유지 MD가 포함된 최종 diff의 타입·전체 테스트·build·SEO 감사·PERFORMANCE.md 예산 결과.
- 생성된 NTE 파티 초기 HTML의 원본 필드 대조 결과와 다른 feature 경로 회귀 없음의 최종 회차 확인.
- 첫 진입·JS 지연/실패·SPA 이동·noindex 진입에서 본문과 리소스 유지, head의 단일 canonical/title 및 보호 태그 유지.
- 기존 언어·모바일/데스크톱 탐색, 광고/동의 기능과 디자인을 보존한 실제 렌더링.
- 배포 후 수치 비교가 필요하면 같은 조건의 독립 반복 측정. 이번 검토는 PSI·INP·CrUX 실측을 하지 않았으므로 점수·가속률·실사용자 CWV 통과를 확정하지 않는다.

이 담당은 추가 구현·빌드·Notion·DB·commit/push·배포를 실행하지 않고 검토 문서만 추가했다.

## 성능 → 디자인 교차 검토

독립 1차 판정 후 [디자인 변경 범위 보고서](2026-10-16-review-nte-seo-design.md)와 실제 파티 페이지 diff를 확인했다. 초기 HTML에 실제 파티를 추가한 변경은 일반 소개로 본문 누락을 가리던 상태를 바로잡는 것으로, 콘텐츠·광고를 숨겨 점수를 높인 작업이 아니다.

모바일 변경은 최상위 `flex-col lg:flex-row` 추가다. root 공용 원자료에서 기존 390×844 모바일의 본문 left 398이 수정 후 left 16/right 368(client 384)로 복구됐고, 데스크톱 첫 카드 3개는 같은 y 550에서 기존 3열을 유지했다. 이는 콘텐츠를 제거한 것이 아니라 모바일에서 기존 본문 노출을 복구한 결과다. 이 담당의 직접 브라우저 관찰은 아니며, 모든 기기/언어/상태의 반응형 통과나 CLS 개선 실측으로 확대하지 않는다.

공용 로컬 검사에서 메타 태그 단일성·인증/CSP/광고 보존, 파티 6개 순서·검색 초기화·SPA 왕복을 확인했다는 자료도 받았다. 배포 후 동일 여부, 독립 PSI 반복·INP·CrUX는 여전히 미검증이다.
