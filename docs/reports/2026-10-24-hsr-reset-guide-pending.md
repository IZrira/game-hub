# HSR 초기화 가이드 초안 및 남은 검증

작성일: 2026-10-24. 공개용 본문은 `docs/drafts/hsr-content-reset-guide.md`, 근거 목록은 `docs/reports/2026-10-24-hsr-reset-primary-sources.md`에 분리했다. 사이트 콘텐츠 등록·Notion 동기화·게시·commit·push는 하지 않는다.

## 후속 등록 승인

사용자가 12만 포인트를 최대 보관 한도로 정정하고 글 등록을 요청했다. 이에 지원 보상을 일일 최대 10회·1회 2,000·미수령 보관 최대 120,000으로 반영하여 게시한다. 앞선 ‘주 12만 보류’와 게시 보류 문장은 과거 검토 이력이다. 사용자 제공 정보와 기존 확인 자료를 대조했으며 모든 항목을 이번에 독립 플레이 검증했다는 뜻은 아니다. Notion은 갱신하지 않는다.

공개 경로: `/gallery/hsr/guides/content-reset-guide`. 기존 기사 등록 구조를 사용하며 외부 출처 링크·Markdown 표·우편물 이미지의 확률 미상 보상 풀은 공개 본문에 추가하지 않는다. 원본·초안·근거·미확정 항목 문서는 함께 보존한다.

### 등록 검증

- TypeScript·build 통과. 빌드 내 SEO 893개 사이트맵 경로 및 성능 예산 검사 통과.
- 기사 본문 일치·보관 한도 문구·기수 예외·기사 런타임 테스트 9개 통과. 제한 샌드박스 임시 파일 ENOENT는 동일 테스트를 추가 권한 환경에서 재실행해 통과했다.
- 성능 역할: 기존 기사별 지연 로딩 구조 유지, 초기 JS gzip 추정 139,688 / 170,000바이트.
- 보안 역할: 외부 링크·Notion 링크·임의 HTML 삽입 없음. Notion 동기화·인증 설정 변경 없음.
- 디자인 역할: 기존 기사 페이지 컴포넌트 유지, 표 없이 짧은 제목·문단·목록 구성. 운영 화면은 배포 후 별도 확인한다. 독립 3인 전체 감사로 간주하지 않는다.
- 기존 AGENTS.md와 무관한 미커밋 보고서는 커밋하지 않는다. GitHub push 이후 자동 배포 결과와 실제 페이지 확인은 최종 응답에서 보고한다.

## 초안에 반영한 내용

### 사용자 보완 자료 반영 상태

아래 기존 보류 목록은 최초 조사 이력으로 보존한다. 후속 사용자 설명을 받아 지원 보상의 일일 적립, 토벌런, 귀중한 우편물, 에이딘 코인, 기억의 파편, 시뮬레이션 런, 잔화 교환, 레진 월 경계, 공훈 및 엔드 콘텐츠 해금 조건을 초안에 추가했다. 이는 사용자 제공 정보를 문체 정리한 것이며 현행 인게임 전 항목을 독립 검증한 것은 아니다. 공개 등록은 아직 보류한다.

- 중복 입력된 지원 보상·토벌런 문장은 한 번만 반영했다.
- 지원 보상: 2,000 × 일 10회 및 오전 5시 갱신은 반영. **주 12만은 보류**했다. 하루 2만을 7일 받으면 14만이므로 단순 일 한도 계산과는 다르다. 별도 주간 제한인지, 미수령 보관 한도 12만인지 도움말 화면으로 확인해야 한다. 임의로 보관 한도라고 고치지 않았다.
- 토벌런의 ‘불필요’는 보편적 단정 대신 선택 파밍·필수 숙제 아님으로 정리했다. 필드 몬스터 재출현 설명을 특수 적·파괴물까지 확대하지 않는다.
- 우편물: 귀중한 우편물의 주간 초기화와 기존 일반 우편물 일일 갱신을 구분했다.
- 에이딘 코인: 두 구매 지역을 모두 반영하되 NPC 이름·각 상점의 구매 한도 공유 여부·판매 수량은 새로 추정하지 않았다. 미라클상 이후 일반 뽑기는 추천 선택지로 표현했다.
- 기억의 파편: 사용자 제공 임무·지역·상호작용·10개·두 번째 선택지 개방 조건을 반영했다. 야누스의 말 명칭으로 문장 내 표기를 통일했다. 원문 해금 조건의 독립 확인은 남아 있다.
- 시뮬레이션 런: ‘신포’를 ‘신용 포인트’로 풀고 33×3=99, 34번째 첫 대상=100 계산을 확인했다. 한 판의 3마리 구성을 전제로 썼으며 모든 모드가 같은 경로라고 확장하지 않았다. 100마리 한도가 드롭 종류별로 동일한지, 차분화와 공유되는지는 남은 검증이다.
- 레진: 월 2회·균형 레벨 3·월 경계 설명을 반영했다. 합성 비용은 추가하지 않았다.
- 공훈: 개척 레벨 13, 선행 임무, 주간·회차 경험치, 유료 두 상품 차이를 반영했다. 유료 보상 전체 목록은 쓰지 않았다. 현재 정식 한국어 상품명·시즌 종료일은 독립 검증 필요.
- 엔드 콘텐츠: 사용자 제공 해금 조건·층수·파티 수·점수 방식을 반영했다. 종말의 사전 개방을 정규 해금 조건 전체와 같다고 쓰지 않았다. 이상 중재 풀별 기록의 적용 기수·정확한 요건, 체크메이트 편성 규칙은 현행 화면 확인 필요.
- ‘각 6주/2주 교대’는 기본 구조로 쓰고 공식 4.6 혼돈 5주 예외를 유지했다. 사용자 원문을 예외 없는 규칙으로 바꾸지 않았다.

## 게시 전 반드시 확인할 항목

### 1. 일일 훈련의 정확한 초기화 시각

일반적으로 알려진 아시아 서버 한국 오전 5시를 현행 인게임 또는 공식 일일 훈련 안내와 직접 대조한다. 기존 조사에는 과거 안내와 일반 서버 시계 자료가 있으나, 엄격한 현행 직접 검증과 구분한다. 초안에는 일일 갱신만 반영하고 시각은 보류했다.

### 2. 지원 보상

- 현행 하루 적립 한도와 미수령 보관 한도를 각각 확인한다.
- 옛 자료의 1만/6만과 후속 자료의 2만/12만을 섞지 않는다.
- 일일 한도 갱신 시각과 이미 적립한 보상의 보존 여부를 확인한다.
- 프로필의 지원 보상 도움말이 필요하다. 확정 전 수치·시각 모두 본문 제외.

### 3. 토벌런

- 일반 필드 적의 재출현 시각을 확인한다.
- 특수 적·저금통·파괴물·일회성 보상은 별도로 확인한다.
- 재출현과 보상 제한을 구분한다. 모든 대상을 동일 일일 초기화로 쓰지 않는다.

### 4. 선주 우편물

- HoYoWiki 모정 항목은 일반 우편물 일 5개, 귀중한 우편물 주 3개로 안내한다.
- 현행 상점의 상품명·구매 횟수·일일 및 주간 갱신 경계를 직접 확인한다.
- 구분 자체는 근거가 있으나 정확한 시각 가이드에 넣기 전 재고 화면으로 대조한다.

### 5. 에이딘 코인

- 플레이 자료의 댄시 주 10개를 현행 상점에서 확인한다.
- 정확한 주간 갱신 시각과 상품명을 확인한다.
- 보유 코인의 소멸이 아니라 구매 한도 갱신이라는 점을 유지한다.

### 6. 기억의 파편

- 정식 한국어 아이템 명칭과 이상한 결정체 상호작용 위치·해금 조건을 확인한다.
- 플레이 자료의 주 10개와 정확한 갱신 시각을 확인한다.
- 주간 무료 수령과 탐색 등 다른 획득 경로를 구분한다.

### 7. 시뮬레이션 런

- 과거 주 100회 제한이 현행에도 유지되는지 확인한다.
- 횟수 단위는 판 수가 아니라 정예·보스 처치 보상인지 대조한다.
- 재료·신용 포인트·유물 경험치 등 드롭별 제한 및 시뮬레이션·차분화 간 공유 여부를 확인한다.
- 점수 보상 통합 공지는 적 드롭 한도의 근거로 대신 쓰지 않는다.

### 8. 잔화 교환

- 월간 갱신 자체는 자료가 있으나 매월 1일 서버 04:00의 현행 직접 확인이 남았다.
- 티켓·운명의 발자취 등 상품별 수량을 현행 상점과 대조한다.
- 스타라이트 교환의 제한과 혼동하지 않는다.

### 9. 레진 합성의 월 경계 시각

월 2개 합성 제한은 반영했다. 정확한 월 경계 시각, 현행 한국어 명칭 및 합성 비용은 인게임 대조 후 추가한다. 주옵션·부옵션 지정에 쓰는 레진 수량과 합성 한도를 혼동하지 않는다.

### 10. 무명의 공훈

- 현행 정식 한국어 표기, 주간 임무 갱신 시각, 주간 경험치 한도, 시즌 종료 시각을 확인한다.
- 외부 전재의 4.6 종료일은 공식 원문 또는 인게임 대조 전 확정하지 않는다.
- 버전 종료일과 공훈 종료일을 같은 날로 추정하지 않는다.

### 11. 엔드 콘텐츠 범위 및 유지 관리

혼돈·허구·종말의 현행 날짜는 초안에 반영했다. 이상 중재 등 추가 모드를 포함하려면 한국어 명칭·보상 주기·시작 및 종료 시각을 별도로 확인한다. 4.6 날짜는 다음 기수에서 갱신하거나 상시 안내와 분리해야 한다.

### 12. 제공된 아카라이브 원문

직접 열기에 실패했다. 원문의 주장과 위 조사 결과를 항목별로 대조하지 못했으므로, 읽었다고 보고하거나 해당 글 전체를 검증 완료로 취급하지 않는다.

## 문서 검수 기준

- 공개용 초안에는 외부 사이트명·외부 링크·Notion 링크·Markdown 표를 넣지 않는다.
- 근거가 부족한 숫자와 시각은 본문에 빈칸이나 임시 확정값으로 넣지 않는다.
- 상시 규칙과 4.6 한정 날짜를 분리한다.
- 코드·운영 데이터 변경이 없는 문서 작업이므로 TypeScript·build는 실행하지 않는다. 신규 문서 재독과 문서 범위 공백 검사를 실시한다.
