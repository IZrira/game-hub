## 확인한 근거

1. `CharacterGuideDetail.tsx`의 import 변경은 기존 공용 sanitizer를 HSR 전용 공개 변환으로 교체한다. 전체 캐릭터·광추·유물·파티 원본을 새로 정적 import하지 않는다. 캐릭터별 manifest와 선택한 JSON 한 개를 요청하는 경로를 유지한다. AbortController·재시도·이전 응답 배제 코드는 변경되지 않았다.
2. 신규 성흔 변환은 현재 가이드 객체를 순회하며 원본을 수정하지 않는 구조다. 새 외부 서비스 요청, 폴링 또는 반복 렌더 타이머를 추가하지 않는다. 기존에도 전체 객체를 한 번 순회해 링크를 정리하므로 순회 차수가 늘어나는 구조가 아니다.
3. 등록 파일의 `characterName`을 읽는 작업은 사이트맵 생성 시에만 실행된다. HTTP 요청마다 93개 소스 파일을 읽는 구조가 아니다. 실제 생성 결과는 공략 경로가 20개 추가됐다. 처음 발견한 3개만의 누락이 아니며, 새 경로도 명시적으로 등록된 가이드와 연결된다.
4. `git diff --name-only -- hsr-hub/data/guides` 결과가 비어 있다. 로컬 비교 수치·추천 장비·공략 본문 원본을 줄여 성능 예산을 맞춘 작업이 아니다. 공개 비교표 제외는 사용자가 승인한 미검증 수치 보류 정책이다.
5. 현재 HSR manifest 93개와 생성 디렉터리 JSON 93개를 직접 대조했다. 기존 manifest 대비 33개 해시가 바뀌었고 총 비압축 JSON 크기는 660,316 bytes다. 가장 큰 파일은 단항 등황 31,890 bytes로 40,000 bytes 예산 이하다. 합계는 모든 캐릭터를 한 페이지에서 내려받는 전송량을 뜻하지 않는다.
6. 오래된 해시 파일 정리는 현재 manifest에 없는 생성 형식의 JSON만 대상으로 한다. 현재 해시 JSON은 보존되며 불필요한 구형 산출물을 다음 배포 디렉터리에 함께 복사하는 일을 막는다.
7. 후속 검토에서 `Gallery.tsx`, `HsrRecommendedCharactersSection.tsx`, `hsr-hub/data/index.ts`의 원본 가이드 import를 생성된 `public-guide-catalog.json`으로 교체한 diff를 추가 확인했다. 목록은 기존처럼 동적 import하고, 추천 영역은 기존 원본 카탈로그 의존을 공개 카탈로그로 대체한다. 타입 전용 `CharacterGuide` import는 런타임 의존이 아니다. 새 전체 카탈로그 요청을 캐릭터별 공략 상세에 추가하지 않는다. 공개 카탈로그는 93개, 비압축 274,641 bytes / 로컬 gzip 56,127 bytes이며 `efficiency1`·`efficiency3` 키가 없다. 목록·장비 추천의 기존 원본 집합 의존을 새로 만든 것이 아니라 공개 변환한 동일 데이터로 대체한 것이다.

## 로컬 production 산출물 용량

부모 담당이 성공한 빌드에서 아래 수치를 전달했다. 이 담당은 별도로 현재 `dist/index.html`의 module entry와 preload를 읽고 `gzipSync`로 JS·CSS 수치를 재계산해 일치함을 확인했다. 빌드·생성기·테스트를 동시에 실행하지 않았다.

- 진입 JS gzip: **25,299 / 32,000 bytes**.
- 진입 JS + HTML modulepreload gzip 합계: **139,853 / 170,000 bytes**.
- 최대 JS chunk gzip: **206,540 / 250,000 bytes**.
- 최대 CSS gzip: **26,847 / 34,000 bytes**.
- HSR 개별 공략 JSON 비압축 최대: **31,890 / 40,000 bytes**, 93개 직접 확인.
- HSR 상세 JSON 비압축 최대: **28,496 / 40,000 bytes**, 부모 빌드 결과 제공값.
- sitemap 914개, 앱 허용 경로 917개: 부모 생성 결과 제공값.

위 값은 로컬 압축 추정치와 파일 크기다. CDN 실제 전송량·속도 향상률·Lighthouse 점수 또는 사용자 CWV로 해석하지 않는다. 이번 검사에서 동일 환경의 이전 production 파일을 보존해 측정하지 않았으므로 전후 가속률은 제시하지 않는다.

## 성능 → 디자인 교차 검토 의견

기존 디자인, 광고, 장비 추천과 분석 본문을 성능 점수 목적으로 제거한 diff는 없다. 공개 성흔 비교표 제외는 미검증 수치를 보류하는 승인 범위이며 원본 데이터는 유지된다. 실제 화면의 정보 계층·공백·탭 동작은 디자인 담당의 브라우저 결과로 추가 확인해야 한다.

## 후속 조건

부모 담당이 최종 타입·테스트·빌드·diff, commit/push, Cloudflare 및 운영 접근을 확인한다. 이 보고서 단독으로 배포 완료나 사이트 전체 성능 통과를 선언하지 않는다.
