# 성능 개선 및 유지 체계 보고서

## 범위

2026-10-15. 이전 배포 56e854e 이후 남은 WW 반응형 이미지, 이미지 우선순위·오류 복구, 목록 이미지 지연 로딩, 광고 예약 작업과 성능 회귀 방지를 적용했다. 디자인·게임 데이터·공략 원문은 변경하지 않았다. Notion 동기화는 실행하지 않았다.

## 개선 전후

- WW 썸네일 소스 56개에서 62개로 확대했다. 방랑자 남녀·속성 매핑은 기존 resolver를 사용하며 기존 56개 큰 썸네일 경로는 보존한다.
- 기존 384px 단일 이미지 대신 192px·384px 후보를 제공한다. 62개 소스 합계 기준 작은 후보 1,333,088 bytes, 큰 후보 3,973,432 bytes로 작은 후보 선택 시 약 66.5% 적다. 실제 전체 페이지 전송량 감소율은 아니며 DPR·화면 크기에 따라 큰 후보를 선택할 수 있다.
- 캐릭터 목록의 첫 이미지에만 high 우선순위를 부여하고 기존 첫 4개 eager·나머지 lazy 정책을 유지했다. 홈 미리보기는 lazy다.
- 썸네일 실패 시 srcset/sizes를 제거하고 원본으로 복구한다. 그 다음 실패는 기존 CDN 대체 경로를 사용한다.
- 해시형 썸네일 정상 응답만 immutable 1년 캐시를 적용한다. HTML·404·다른 응답과 보안 헤더는 유지한다.
- 아이템 및 남녀 분리 아이템 이미지에 lazy·async decoding을 추가했다. 전체 목록·필터·검색·기존 배치를 유지했다.
- 숨겨진 광고 슬롯은 반복 rAF 대신 ResizeObserver로 가시 폭 변화를 기다린다. 미설정 슬롯은 예약하지 않고 언마운트 시 프레임·타이머·관찰자를 해제한다. AdSense 외부 스크립트 로딩과 광고 정책은 변경하지 않았다.

이전 배포에서 확인된 번역 크기 감소(비압축): WW 카멜리아 한국어 상세 746,032→13,532 bytes(98.2%), HSR 에버나이트 상세 33,099→7,614 bytes(77.0%), WW 한국어 공략 818,847→7,724 bytes(99.1%), HSR 한국어 공략 249,965→20,536 bytes(91.8%). 전체 페이지 속도 개선율로 해석하지 않는다.

## 점검 후 유지한 항목

폰트는 이미 비차단 stylesheet preload와 display=swap을 사용한다. CSS는 UI 소스만 스캔한다. 측정 근거 없이 폰트 교체·광고 지연·공통 CSS 대량 삭제·목록 가상화를 추가하지 않았다. 검색·접근성·스크롤 회귀 위험이 있는 조치는 이번에 강제로 적용하지 않았다.

## 재발 방지

docs/guides/PERFORMANCE.md를 유지 기준으로 추가하고 README에 연결했다. scripts/audit-performance.js 및 npm run perf:audit로 검사하며 GitHub Quality Gate의 빌드 다음 단계에서 자동 실행한다. 예산 초과 테스트도 포함한다.

로컬 빌드 기준 현재값 / 예산(bytes):

- 진입 JS gzip: 43,574 / 56,000.
- 진입 JS + HTML modulepreload gzip 합계: 158,128 / 220,000.
- 개별 CSS 최대 gzip: 26,898 / 34,000.
- 개별 JS chunk 최대 gzip: 206,386 / 250,000.
- 공략 JSON 최대: 31,460 / 40,000 (150개 검사).
- 공략 번역 팩 최대: 20,536 / 28,000 (한·영 4개 검사).
- 작은 썸네일 최대: 28,150 / 40,000.
- 큰 썸네일 최대: 85,884 / 110,000.

gzip은 로컬 계산이며 실제 CDN 전송량이 아니다. 진입 modulepreload 합계는 HTML 선언 기준으로 이후 동적 요청 전체를 포함하지 않는다. 콘텐츠가 늘면 원인을 분석하고 승인된 근거와 함께 예산을 조정한다.

- 전체 회귀 테스트 31개 파일·262개 테스트 통과, 데이터 검증 및 성능 예산 검사 통과.

## 한계 및 후속 관찰

Lighthouse 전후 3회 중앙값, LCP·INP·CLS 및 실제 사용자 현장 데이터는 이번 환경에서 확보하지 않았다. 따라서 모든 기기에서 같은 점수나 속도를 보장하지 않는다. 성능 구조와 자동 예산 검사 도입은 완료했으나 체감 성능 비교 측정은 미완료다. 서드파티 광고·CDN·네트워크 상태는 코드 예산만으로 통제할 수 없다. 동일 조건의 측정과 Search Console 현장 지표 관찰은 유지 기준 문서에 명시했다. 데이터 검사에는 기존 키레네의 혼합 유물 표기 "속도 2세트 + 속도 2세트"가 단일 도감 항목이 아니라는 경고 2건이 있으며 이번 작업에서 공략 내용은 변경하지 않았다. Git LF/CRLF 안내도 존재하나 공백 검사 오류는 없다.
