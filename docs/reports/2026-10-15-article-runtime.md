# 후속 성능 개선: 분석 가이드 상세의 글 단위 로딩

기준 커밋 12e7a3d. 일반 GuideArticle 상세가 전체 guideArticles 본문을 가져오는 의존을 제거했다. 메타데이터·관련 글은 기존 요약에서 읽고 실제 본문은 선택한 공개 글의 JSON만 요청한다. NTE 전용 캐릭터 세팅 상세는 이번 범위에서 변경하지 않았다.

## 변경

- 로컬 원문을 기존 공개 콘텐츠 정제 규칙으로 처리한 뒤 공개 상태인 글만 해시 JSON으로 생성한다. 한글 slug는 주소의 키로 유지하고 저장 파일명은 안전한 영문 이름과 내용 해시를 사용한다.
- 원본 글·제목·메타데이터·관련 글 순서·기존 디자인은 유지한다. 초기 HTML과 사이트맵 생성은 기존 원본을 계속 사용한다. Notion 동기화는 하지 않았다.
- 요청 실패 시 재시도, 다른 글 이동 시 AbortController 취소 및 늦은 이전 응답 무시, 잘못된 글 응답 차단을 추가했다.
- 로딩 중에도 요약 기반 SEO 메타데이터를 유지하고 일시적 로딩을 없는 페이지/noindex로 처리하지 않는다.
- 정상 해시형 JSON에만 1년 immutable 캐시를 적용한다. HTML·404·보안 헤더는 유지한다.
- 기존 요약 생성기에 연결되어 개발·테스트·빌드 시 로컬에서 생성한다. 외부 동기화나 이미지 다운로드를 실행하지 않는다.
- 글별 JSON 24,000 bytes 예산을 빌드 성능 감사에 추가했다.

## 검증 범위

공개 글 32개의 생성 파일과 원본 전체 대조, 내용 해시, 없는 경로 무요청, 503 후 재시도, 이동 후 지연 응답 무시·요청 취소, 다른 글 응답 거부, 캐시 정상/304/404/HTML 구분과 보안 헤더 보존을 검사했다. 타입·전체 테스트(33개 파일·276개 테스트)·빌드·890개 경로 SEO·성능 예산 검사를 통과했다. 브라우저에서 에스퍼 사이클 분석의 제목과 본문 섹션이 표시되고 로딩·오류 상태가 남지 않음을 확인했다. diff 검증 후 commit/push/배포 결과는 완료 보고로 제공한다.

현재 글별 JSON 최대 크기는 14,643 bytes / 예산 24,000이다. 초기 JS gzip 합계는 138,584 bytes / 예산 170,000이며 기준 빌드의 138,619 bytes와 사실상 비슷하다. 이번 목적은 초기 JS 추가 축소가 아니라 상세 진입 시 불필요한 다른 글의 다운로드·파싱을 피하는 것이다.

## 한계

전체 원문 JSON은 94,405 bytes이나 개별 JSON과 원본 소스의 비교는 실제 압축 전송량/로딩 시간 개선율이 아니다. 글 로딩에는 새 JSON 요청이 하나 추가된다. LCP·INP·CLS 실측은 확보하지 않았다. 이환 전용 세팅 페이지에 남아 있는 전체 원문 의존은 다음 후보이며 일반 분석 상세와 구분한다. 기존 AGENTS.md 미커밋 변경은 보존하고 제외한다. Git LF/CRLF 경고 및 기존 데이터 경고는 이번에 수정하지 않는다.
