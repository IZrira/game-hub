# HSR 분석 10개 변경 범위 성능 검토

- 검토일: 2026-10-29, 한국 시간.
- 기준: `d2f4b8f` 이후 작업 트리. 성능 담당 에이전트의 독립 정적 검토이며 사이트 전체 성능 평가가 아니다.
- 대상: 미샤·반디·부현·블랙 스완·삼포·설의·스파클·아케론·어공·어벤츄린 분석과 갱신일.

## 확인 결과

- **PASS — 로딩 구조 보존.** 구현 diff는 가이드 원본 10개에 한정된다. 페이지·라우터·생성기·의존성·광고·캐시 코드 변경은 없다. `hsr-hub/pages/CharacterGuideDetail.tsx:5`는 해시 manifest를 사용하며 `:379` 이후 선택한 글만 요청하고 `AbortController`로 이전 요청을 정리한다. 전체 가이드·장비·파티 DB의 eager import를 새로 추가하지 않았다.
- **PASS — 콘텐츠 갱신 경로 유지.** `scripts/generate-hsr-guide-runtime.js:54`는 JSON 본문 해시로 URL을 생성한다. 변경된 원문은 빌드에서 새 URL로 배포되어야 하며 기존 URL에 다른 본문을 덮어쓰는 방식이 아니다. `scripts/prerender-meta.js:1864` 이후는 공개 분석의 장점·주의점·운용 순서를 초기 HTML에 포함한다. 내용을 숨기거나 줄여 성능 점수만 높이는 변경은 없다.
- **PASS — 생성 데이터·예산.** 주 담당이 문장 축약 후 최종 TypeScript와 production build exit 0, 894개 사이트맵 URL의 SEO 감사 및 성능 예산 통과 결과를 전달했다. 최종 빌드 출력은 entry gzip 25,305/32,000 bytes, initial JS gzip 139,859/170,000 bytes, 최대 chunk gzip 206,540/250,000 bytes, 150개 HSR·WW 글 JSON 최대 32,376/40,000 bytes다. 성능 담당은 축약 전 생성 manifest가 가리키는 변경 10개 JSON을 별도로 읽어 검토일 2026-10-29, 운용 4단계·팁 3개 반영을 확인했다. 주 담당이 최종 10개 JSON에서 확인한 용량은 5,329~15,180 bytes다. 이 수치는 로컬 파일 크기이며 실제 CDN 전송량이나 속도가 아니다.
- **UNVERIFIED — 실측.** 이 담당은 브라우저 직접 진입·SPA 이동·cold/warm 캐시·FCP/LCP/CLS/TBT/INP를 측정하지 않았다. 실제 전송량·체감 속도 개선·현장 CWV 통과를 주장하지 않는다.
- **N/A — 운영 부하 시험 및 의존성 최적화.** 콘텐츠 교체 범위이며 실행하지 않았다.

## 후속 확인

1. TypeScript와 production build의 SEO/성능 예산 통과 확인 완료. 예산 상향 없이 통과했다.
2. 변경 10개 글의 해시 JSON 반영 확인 완료. 주 담당은 최종 HEAD 대비 `analysis`·`lastUpdated` 이외 원본 필드가 동일함과 10개 런타임·초기 HTML 반영을 확인했다. 축약 전 전체 회귀는 71개 파일·553개 검사 통과, 최종 축약 후 관련 회귀는 5개 파일·73개 검사 통과로 전달받았다. 최종 전체 회귀를 다시 실행한 것으로 표현하지 않는다.
3. 운영 배포 commit 일치와 대표 가이드 접근 확인. 미검증 실측을 정적 PASS로 바꾸지 않는다.

판정: 정적 로딩 구조와 생성 파일 예산 범위 PASS. 운영·브라우저 실측을 포함한 성능 전체 통과로 해석하지 않는다.

## 교차 검토

- 디자인·UX: diff에서 CSS·레이아웃 변경 없이 모바일 읽기 부담을 줄이는 문장 축약만 확인했다. 콘텐츠를 숨겨 예산을 통과시키는 변경이 아니다. 실제 화면 검증 결과는 주 담당의 별도 증거를 따른다.
- 보안: sanitizer·권한·캐시·광고 코드 변경 없이 문자열 데이터를 교체했다. 보안 처리를 제거하거나 완화해 성능을 높인 변경은 정적 diff에서 발견하지 못했다. 이는 동적 보안 시험을 대체하지 않는다.
