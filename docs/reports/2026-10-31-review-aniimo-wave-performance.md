# Aniimo 웨이브 군도 추가 — 성능 독립 검토

## 실행 정보

- 실행일: 2026-10-31, 한국 시간.
- 담당 에이전트: `/root/aniimo_seo`, 이번 검토 역할은 성능. 앞서 같은 작업의 SEO·서식지 연결 코드를 작성했으므로 해당 코드에 대한 작성자 독립성에는 한계가 있다. 수집기·런타임 생성기·상세 요청·목록 식별자는 다른 담당이 구현한 코드를 별도로 확인했다.
- 기준: `docs/guides/THREE_ENGINEER_REVIEW.md`, `docs/guides/PERFORMANCE.md`, `rira-performance-check`.
- 대상: `main`, 기준 HEAD `7d056e89983b97d4f97e330d32651476967c3a36` 위의 미커밋 웨이브 군도 추가 변경. 운영 배포 버전과 일치한다고 판단하지 않는다.
- 환경: Windows, Node v24.19.0, npm 11.17.0. 한국어 로컬 파일·소스 검사. 이번 담당은 브라우저 계측을 실행하지 않았다.
- 범위: 신규 29종·42형태의 데이터 증가와 기존 86종 보존, 데이터 전송 구조, 빌드 예산. 사이트 전체 실사용 성능 평가가 아니다.
- Notion 동기화·운영 쓰기·부하 테스트·배포: 실행하지 않음. 구현 코드는 변경하지 않고 이 보고서만 작성했다.

## 독립 1차 결론

상세 데이터를 선택한 항목의 별도 JSON으로 받는 구조가 유지되었으며, 신규 도감 전체 원본이 프런트엔드 정적 의존으로 유입되는 회귀는 확인하지 못했다. 요약 데이터는 신규 종·형태만큼 증가했다. 다만 이 결과는 로컬 파일 용량과 코드 구조에 대한 제한된 판정이다. 빌드 예산의 최종 결과와 실제 화면 지표는 아래 실행 상태에 따라 구분한다.

## 실제 용량 측정

측정 방법: Node `fs.readFileSync` 바이트 길이, `node:zlib`의 `gzipSync`. 이전 요약은 `git show HEAD:aniimo-hub/data/aniimo-summary.json`을 읽었다. gzip은 로컬 추정이며 CDN 실제 전송량이 아니다.

| 대상 | 비압축 bytes | 로컬 gzip bytes |
| --- | ---: | ---: |
| 이전 86종 요약 | 537,821 | 34,108 |
| 현재 115종 요약 | 667,774 | 44,720 |
| 증가량 | 129,953 | 10,612 |
| 보존한 기존 원본 JSON | 1,726,898 | 98,853 |
| 신규 지역 원본 JSON | 513,482 | 32,001 |
| 신규 상세 중 최대: 스프링거 | 25,571 | 2,533 |
| 신규 상세 중 최소: 플로거 | 8,480 | 1,596 |
| 전체 상세 중 최대: 기존 몽실양 | 33,769 | 2,786 |

- 기존 86종 + 신규 29종 = 총 115종. 신규 형태 42개.
- 신규 상세 29개 합계 380,470 bytes. 전체 상세 115개 합계 1,670,767 bytes. 이 합계를 페이지 하나가 다운로드한다는 뜻이 아니다.
- 신규 상세는 모두 40,000 bytes 미만이다. 현재 자동 예산 검사는 HSR 상세를 대상으로 하므로 이 수치는 Aniimo의 강제 예산 통과 주장이 아니라 같은 크기 기준과의 수동 비교다.
- 요약의 증가량을 페이지 가속률 또는 지연률로 환산하지 않았다.

## PASS — 구조 검사

1. **선택한 상세만 요청**: `aniimo-hub/pages/CharacterDetail.tsx`는 `getAniimoId(summaryItem)`으로 `/assets/data/aniimo/<id>.json` 한 경로를 요청한다. 기존 `001.json`과 신규 `wave-archipelago-001.json`이 분리된다. 형태 전환은 이미 받은 해당 종의 형태 배열을 사용하며 전체 신규 지역 파일을 요청하지 않는다.
2. **응답·이동 처리**: 상세 요청은 `AbortController`를 사용하고 effect 정리에서 중단한다. 로드한 응답의 식별자를 검사하여 동명이 아닌 같은 번호의 기존 항목이 표시되지 않도록 한다. 이미지 로딩 완료를 기다려 상세 이동을 수행하는 코드는 추가되지 않았다.
3. **프런트엔드 원본 유입 없음**: `aniimo-hub`의 TypeScript·TSX에서 `aniimo.json`·`wave-archipelago.json` 정적 import를 검색했으며 결과가 없었다. 페이지는 `aniimo-summary.json`을 사용한다. 원본 로더는 Node 생성 스크립트에 한정된다.
4. **목록 이미지 정책 보존**: 목록의 정사각형 이미지 컨테이너와 `loading="lazy"`가 유지된다. 이미지 전부를 preload하거나 캐시 무효화 query를 넣는 변경은 없다. hero는 기존과 같이 일반 이미지 요청이며 신규 수집기가 해당 주소를 제공한다.
5. **수집과 빌드 분리**: `fetch-aniimo-wave-data.js`의 원격 수집은 별도 명령이다. 기존 `build`는 저장된 로컬 원본을 조합하며 원격 공식 위키 수집이나 Notion 동기화를 호출하지 않는다. 수집은 순차·30초 제한으로 무제한 병렬 요청을 만들지 않는다.
6. **예산 기준 보존**: `scripts/audit-performance.js` 및 성능 기준의 예산을 이번 추가에 맞춰 높인 변경은 없다. 콘텐츠·이미지·광고를 제거해 예산을 맞추는 수정도 확인하지 못했다.

## 검증 상태

- 이 담당의 앞선 구현 단계 타입 검사: PASS. 이후 다른 담당의 신규 테스트가 추가되었으므로 최종 통합 상태를 대체하지 않는다.
- 관련 서식지·목록 테스트: 3개 파일 36개 PASS. 최초 샌드박스 실행의 임시 모듈 ENOENT는 허용된 외부 실행에서 재현되지 않았다.
- 통합 타입 검사: 첫 빌드에서 `tests/aniimo-wave-data.test.ts`의 JSON 추론 타입 관련 TS2322를 발견해 주 담당에게 보고했다. `AniimoEntry[]` 타입 명시로 수정했고 주 담당의 재검사 session 99038이 exit 0으로 종료되었다.

- 전체 회귀 테스트: 주 담당 실행 결과 76개 파일·591개 테스트 PASS. 마지막 지역 독점 표현 가드 추가 후 관련 4개 파일·18개 테스트도 PASS로 전달받았다. 테스트를 다시 중복 실행하지 않았다.
- 주 담당은 공식 원문 42형태 재비교와 이미지 주소 40개 HEAD 응답 성공을 확인했다. HEAD 성공은 실제 이미지 전송 시간·디코딩 측정으로 해석하지 않는다.
- 이 담당은 중복 빌드·예산 감사 명령을 실행하지 않았다.
