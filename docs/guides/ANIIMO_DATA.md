# Aniimo 공식 도감 추가·검증

## 원본과 식별자

- 기존 86종 원본: `aniimo-hub/data/aniimo.json`. 웨이브 군도 추가 작업에서는 수정하지 않는다.
- 신규 지역 원본: `aniimo-hub/data/wave-archipelago.json`. 2026-10-31 공식 목록은 29종·42형태다.
- 결합 로더: `scripts/lib/aniimo-catalog.js`. 이름과 내부 식별자 중복을 검사한다.
- 기존 항목은 번호를 내부 ID로 유지한다. 신규 항목은 `wave-archipelago-001`처럼 지역 접두사를 사용하고, 공개 번호 `001`은 그대로 표시한다.
- 상세 파일명·비교 선택·진화 대상 조회는 내부 ID를 사용한다. 공개 캐릭터 URL은 기존처럼 이름을 사용한다. 신규 지역에 기존 번호 기반 영문명·진화 조건을 적용하지 않는다.

## 명시적으로 공식 데이터 갱신을 요청받았을 때

1. `git status`와 기존 원본 해시를 확인한다.
2. 공식 위키의 웨이브 군도 목록과 형태 링크를 확인한다.
3. `node --use-system-ca scripts/fetch-aniimo-wave-data.js`를 실행한다. 수집기는 전체 수집·기본 검증 이후 신규 지역 파일만 쓴다. 목록 수·번호 또는 URL 구조가 바뀌면 중단하므로 공식 변경을 검토한 뒤 처리한다.
4. `node --use-system-ca scripts/verify-aniimo-wave-source.js`로 저장한 이름·형태·그림·7개 능력치·설명·출현 지역·전투/고유 스킬 본문을 공식 HTML과 다시 대조한다.
5. 새 이미지와 공식 진화 경로를 실제 화면에서 확인한다. `evolutionRoutes`는 공식 HTML 트리의 경로를 보존하며, 번호 인접성으로 진화 관계를 추정하지 않는다.
6. `npm run generate:aniimo-runtime`으로 요약과 종별 상세 JSON을 생성하고 기존 원본·상세 URL 보존을 확인한다.
7. AGENTS.md의 타입 검사 → 전체 빌드 → diff 검토 → 관련 테스트·화면 검증 → 허용된 commit/push·배포 확인 절차를 따른다.

일반 빌드는 로컬 원본만 읽으며 공식 위키 수집과 Notion 동기화를 실행하지 않는다. 예전 `fetch-aniimo-data.js`는 지역별 중복 번호가 있는 현재 공식 목록에서 원본을 덮어쓰지 않도록 중단한다.

## 공식 미제공 정보

- 같은 일러스트를 공유하는 형태는 그림만으로 형태를 단정하지 않는다.
- 부엉파·홀부엉 계보의 `10574` 아이콘은 현재 도감으로 이름을 확정하지 못해 미확인으로 표시한다.
- 웨이비핀·서지윙 폭풍 형태 계보의 성장기 이미지는 공식 URL이 비어 있다. 다른 그림·이름·링크로 대체하지 않는다.
- `미확인 구역`은 원문을 유지하는 일반 텍스트다. 독립 지리 페이지나 해당 경로 링크를 만들지 않는다.
- 신규 지역의 출현 장소가 한 곳만 적혀 있어도 독점 출현을 의미한다고 추정하지 않는다.
- 신규 공식 속성 `땅`을 기존 `바위` 상성 수치에 임의로 연결하지 않는다. 새 데이터의 공식 명칭을 보존하며, 상성 계산 확장은 공식 관계 검증을 별도로 거친다.

## 경로와 회귀 검증

신규 지역의 `초승달 만`은 `wave-archipelago--초승달-만` 위치 경로를 사용한다. 기존 별칭의 `고래첨벙 해안` 이동과 기존 14개 서식지 집계는 보존한다. 지역 페이지는 공식 형태의 출현 지역 목록에서 산출한다.

- `tests/aniimo-wave-data.test.ts`: 기존 원본 해시, 29종/42형태, 동일 번호 분리, 공식 표본과 미확인 노드.
- `tests/aniimo-region-identity.test.tsx`: 상세 요청·응답 검증, 비교 선택, 기존 영문명/조건 보호, 미확인 비링크.
- `tests/aniimo-wave-locations.test.ts`: 새 지역 네임스페이스·집계·미확인 구역 제외.
- 기존 `tests/aniimo-habitats.test.ts`는 기존 14개 서식지를 그대로 검증한다.
