# 성능 유지 기준

2026-10-15. HSR·WW·NTE·Aniimo 공통 개발 기준이다. AGENTS.md의 작업·검증·Notion 동기화 규칙을 함께 따른다.

## 변경할 때 지킬 것

- 도감 상세와 공략은 해당 항목에 필요한 데이터와 번역만 로드한다. 전체 DB를 상세 페이지의 정적 의존으로 되돌리지 않는다.
- 원본 로컬 데이터는 유지한다. 빌드 산출물 생성과 Notion 동기화는 별개이며 성능 검증을 위해 Notion을 임의 실행하지 않는다.
- 초기 HTML의 본문·링크를 전체 화면 로더로 가리지 않는다. 초기 HTML과 사이트맵 생성·SEO 감사를 유지한다.
- 목록 이미지는 표시 크기에 맞는 후보와 정확한 sizes를 제공한다. 우선순위 high는 실제 첫 화면 핵심 이미지에만 사용한다. 나머지는 lazy 및 async decoding을 우선한다.
- 썸네일 실패 시 srcset을 제거한 뒤 원본/CDN 대체 경로로 복구한다. 기존 캐릭터·성별·속성 매핑을 대조한다.
- 고정 비율 이미지 영역과 광고 영역을 유지한다. 목록 가상화나 content-visibility는 검색·스크롤·레이아웃 검증 없이 적용하지 않는다.
- 폰트의 비차단 로딩과 display=swap을 유지한다. 광고 코드를 제거하거나 로딩 정책을 바꿔 수치만 개선하지 않는다.
- 숨겨진 광고 슬롯에 매 프레임 재시도를 반복하지 않는다. 관찰자와 예약 작업은 해제한다.
- 해시 파일만 immutable 장기 캐시로 제공한다. HTML·오류 응답에 장기 캐시를 적용하지 않는다.
- Tailwind 스캔은 UI 소스로 제한한다. 문서·백업·DB 전체를 CSS 생성 대상으로 추가하지 않는다.

## 자동 검사

TypeScript → 테스트 → npm run build → npm run perf:audit → git diff --check → diff 검토.

GitHub Quality Gate에서도 빌드 후 perf:audit를 실행한다. 예산 초과는 실패 처리한다. 기준을 조용히 올리지 말고 원인과 필요성을 보고서에 적는다.

현재 예산(bytes): 진입 JS gzip 56,000, 진입 JS와 HTML modulepreload 합계 gzip 220,000, 개별 CSS gzip 34,000, 개별 JS chunk gzip 250,000, 캐릭터별 공략 JSON 40,000, 공략 번역 팩 28,000, WW 작은 썸네일 40,000, 큰 썸네일 110,000.

한 파일 예산만으로 전체 경로 비용을 보장하지 않는다. 동적 chunk 개수·초기 정적 의존·실제 네트워크도 별도로 확인한다. 수치는 로컬 gzip 추정과 비압축 파일 크기로 구분한다.

## 이미지 갱신

공식 생성기: node --use-system-ca scripts/generate-ww-card-thumbnails.js

신규 소스만 다운로드하며 기존 큰 썸네일을 재사용한다. 원본 그림 변경 시 명시적으로 --refresh를 붙인다. 빌드에서 네트워크 다운로드를 실행하지 않는다. 생성 후 manifest, 해시, 이미지 치수, 원본 대비 그림·크롭을 확인한다.

## 실제 체감 성능 검증

홈, WW/HSR 목록, 캐릭터 상세, 세팅 공략을 같은 조건으로 비교한다. 모바일 390px와 데스크톱, 콜드/웜 캐시, 네트워크·CPU 제한, 광고 조건, 측정 버전과 날짜를 기록한다. 각 조건을 3회 이상 측정해 중앙값을 비교한다.

LCP·CLS·INP는 목표와 실측을 구분한다. 현장 데이터가 있으면 75백분위 LCP 2.5초 이하, CLS 0.1 이하, INP 200ms 이하를 목표로 삼는다. 단일 실험실 실행으로 실제 사용자 통과를 주장하지 않는다. INP는 상호작용/현장 데이터 없이 확정하지 않는다.

측정 도구 또는 전후 기준이 없으면 미측정이라고 적는다. 데이터 99% 감소를 페이지 99% 가속으로 표현하지 않는다. 성능 점수 9.5 같은 임의 점수는 완료 기준이 아니다.
