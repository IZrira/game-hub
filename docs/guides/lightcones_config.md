> **문서 용도**: HSR 허브의 광추(Light Cone) 데이터를 정규화하고 관리하기 위한 기술 표준 및 데이터 작성 규칙 가이드입니다.

# 광추 페이지 데이터 설정 가이드

본 문서는 HSR 허브의 광추(Light Cone) 데이터를 관리하고 정규화하는 규칙을 정의합니다.

## 1. 기본 구조 (`HsrLightCone` 인터페이스)
모든 광추 데이터는 `hsr-hub/types/index.ts`에 정의된 `HsrLightCone` 타입을 준수해야 합니다.

## 2. 상세 스탯 설정 (`createDetailedBaseStats`)
레벨별 슬라이더 기능을 위해 기초 스탯은 반드시 `createDetailedBaseStats` 팩토리 함수를 사용하여 8단계 배열로 설정합니다.
- **배열 순서**: [1, 20, 30, 40, 50, 60, 70, 80] 레벨 순서
- **해당 스탯**: 기초 HP, 기초 공격력, 기초 방어력

```typescript
"baseStats": createDetailedBaseStats(
  [hp1, hp20, hp30, hp40, hp50, hp60, hp70, hp80],
  [atk1, atk20, atk30, atk40, atk50, atk60, atk70, atk80],
  [def1, def20, def30, def40, def50, def60, def70, def80]
)
```

## 3. 승급 재료 설정 (`ascensionMaterials`)
승급 재료는 유효한 승급 단계마다 필요한 모든 재료를 `createMaterial` 함수를 사용하여 정의합니다. 현재 프로젝트의 규칙에 따라 **80레벨 데이터**를 필수로 포함하며, 다음과 같은 원칙을 준수합니다.

- **함수**: `createMaterial(이름, 수량, 등급)`
- **필수 레벨 단계**: 20, 30, 40, 50, 60, 70, **80**
- **80레벨 설정 규칙**: 80레벨 항목은 **70레벨 항목과 동일하게** 설정합니다. (UI 표시 및 계산 로직 일관성 유지 목적)
- **재료 전수 명시 규칙 (중요)**: 원본 텍스트에 기재된 모든 등급의 재료를 누락 없이 명시합니다. 고레벨(60~80) 단계에서 하위 등급 재료(2성, 3성 아이템 등)를 생략하거나 단순화하지 않고 전체 리스트를 포함하여 정의해야 합니다.

```typescript
"ascensionMaterials": [
  { "level": 20, "items": [createMaterial("신용 포인트", 5000, 3), ...] },
  ...
  { "level": 70, "items": [
    createMaterial("신용 포인트", 385000, 4), 
    createMaterial("하위 재료", 20, 2), // 하위 등급 포함
    createMaterial("중위 재료", 20, 3), // 중위 등급 포함
    createMaterial("상위 재료", 14, 4)  // 상위 등급 포함
  ] },
  { "level": 80, "items": [/* 70레벨과 동일하게 전체 리스트 복사 */] }
]
```

## 4. 스킬 및 설명 (`skill`)
- **S1 vs S5**: `description` 필드에는 S1 기준의 설명을 넣고, `descriptions` 배열에는 S1부터 S5까지의 모든 단계를 배열로 넣습니다.
- **한국어 표준**: 모든 텍스트는 공식 번역을 따르며, 인게임 용어(예: 격파 특수효과, 기본 확률 등)를 정확히 사용합니다.

## 5. 기타 규칙
- **운명의 길**: 필드 명칭은 공식 번역(예: 공허, 화합, 파멸 등)을 사용합니다.
- **데이터 위치**: `hsr-hub/data/lightcones/[운명의길].ts`
- **게임 ID**: `gameId: "hsr"`을 명시하여 타 게임 데이터와 구분합니다.
- **성급**: 3, 4, 5 수치로 관리합니다.
