# 명조(Wuthering Waves) 스킬 입력 가이드 작성 가이드라인

이 문서는 캐릭터 메커니즘의 복잡도에 따라 **A타입(상세 분석형)**과 **B타입(간결 요약형)**으로 구분하여 작성하기 위한 표준 템플릿입니다.

---

## 1. [A타입] 상세 분석 및 메커니즘 강조형
복잡한 스택 관리와 여러 단계의 효과 설명이 필요한 캐릭터용 템플릿입니다. (예: 복링)

### 특징 (Features)
* **데이터 구조 필수 설정:** `hideGauge: true`를 설정하여 최상단의 자동 게이지 이미지를 숨깁니다.
* 캐릭터의 핵심 역할 및 운용법 요약 (불렛 포인트 사용)

### 설명 (Explanation)
* **소제목 형태:** 텍스트 상단에 `설명` 키워드를 배치합니다.
* **인라인 이미지:** `[파일명.webp]` 형식을 사용하여 섹션 내에 이미지를 배치합니다.

### 특수 에너지 (Special Energy)
* **소제목 형태:** 텍스트 상단에 `특수 에너지` 키워드를 배치합니다.
* **상세 내용:** 획득/소모 조건, 상태 변화, 파티 시너지 등을 기술합니다.
* **문단 구분:** `·` 기호를 기준으로 문단을 나누어 시인성을 높입니다.

### 메커니즘 설명 (Mechanism Explanation)
* **소제목 형태:** 텍스트 상단에 `메커니즘 설명` 키워드를 배치합니다.
* 특정 스킬 발동 후 연계되는 특수 조작법을 기술합니다.

---

## 2. [B타입] 개요 및 직관적 조작형
메커니즘이 단순하거나 특정 상태 진입 조건이 명확한 캐릭터용 템플릿입니다. (예: 알토, 양양)

### 개요 (Overview)
* 핵심 메커니즘(회복 조건, 상태 진입 조건)을 텍스트로 설명합니다.
* 필요 시 게이지 이미지(`[파일명.webp]`)를 상단에 배치할 수 있습니다.

### 조작 입력 (Input Guide)
* **소제목 형태:** 텍스트 상단에 `조작 입력` 키워드를 배치합니다.
* **작성 형식:** `· 스킬명: 조건 충족 시, {{MOUSE_L}} 조작 방식`
* 사용 가능한 아이콘: `{{MOUSE_L}}`, `{{MOUSE_R}}`, `{{KEY_E}}`, `{{KEY_Q}}`, `{{KEY_R}}`, `{{KEY_SHIFT}}`, `{{JUMP}}` 등

---

## 3. 데이터 적용 가이드 (JSON/TS)

### 로컬라이징 (ww_characters_ko.json)
* **A타입:** 모든 내용을 `overview` 필드에 통합하여 작성합니다. (UI에서 `inputs`의 '조작 입력' 타이틀 자동 노출을 피하기 위함)
* **B타입:** `overview`에는 개요를, `inputs` 배열에는 개별 조작법을 작성합니다.

### 캐릭터 데이터 (character.ts)
```typescript
skillInput: {
  overview: "character.[id].skillInput.overview",
  hideGauge: true, // A타입 필수, B타입 선택
  inputs: [] // A타입은 빈 배열, B타입은 인덱스 나열
}
```
---

## 4. 에셋 관리 및 이미지 매핑 규칙 (Asset Management)

### 4.1. 조작 아이콘 (Keycaps)
* **표준 형식:** `[key e.webp]`, `[mouse left.webp]`, `[left shift.webp]`
* **렌더링 로직:** 
    * `renderDescriptionWithIcons`를 통해 자동으로 리포지토리의 대문자 파일명(예: `key%20E.webp`)으로 매핑됩니다.
    * `[key e]`와 같이 확장자가 없는 구형 형식도 호환되지만, 명확성을 위해 `.webp` 포함 형식을 권장합니다.

### 4.2. 조화도 파괴 (Concert Dissipation)
* **파일 명칭:** `조화도 파괴.webp`
* **위치:** `riragameinfo/ww images/skills/[폴더명]/`
* **주의:** 공용 무기 아이콘이 아닌 **캐릭터별 고유 이미지**를 우선적으로 사용합니다. (예외 발생 시에만 `common/concert/` 참조 가능하나 현재는 캐릭터별 고유 이미지가 표준)

### 4.3. 일반 공격 (Basic Attack)
* **파일 명칭:** `일반 공격.webp` (고정)
* **매핑 로직:** UI상에서 "기본 공격"으로 표시되더라도, 실제 파일 시스템에서는 항상 `일반 공격.webp`를 참조하도록 강제 매핑되어 있습니다.

### 4.4. 경로 인코딩 (Encoding)
* 모든 GitHub 에셋 경로는 `safeEncodeURIComponent`를 통과해야 합니다. 이는 NFD(맥)와 NFC(윈도우/리눅스) 간의 한글 자소 분리 이슈 및 특수 문자(공백, 괄호)로 인한 404 오류를 방지하기 위함입니다.
