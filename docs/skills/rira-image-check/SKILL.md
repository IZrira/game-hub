# 이미지점검

호출: `이미지점검 [게임] [캐릭터/장비]` 또는 `$rira-image-check`.

대상 프로젝트는 `D:\rira game hub\game-hub`, 코드 remote는 `IZrira/game-hub`, 이미지 저장소는 `IZrira/riragameinfo`다. 현재 요청, `AGENTS.md`, 해당 경로 지침과 `git status`를 확인한다. 진단만 요청하면 수정·commit·push하지 않는다.

## 필요한 경로만 추적

1. 사용자가 지정한 페이지/이미지부터 찾는다. 게임·이름·기대 이미지와 현재 fallback을 구분하고 목록→상세 요청을 함께 본다. 모든 허브·파일을 무조건 스캔하지 않는다.
2. 페이지가 실제 사용하는 런타임 데이터·파서·공통 이미지 컴포넌트를 추적한다. 원본 필드와 최종 파일명·URL을 대조한다. 숫자가 포함된 재료명에서 `210x25`는 이름 `210`과 수량 `25`로 분리돼야 한다. 원본이 정상인데 변환이 잘못됐다면 원본을 고치지 않는다.
3. 제공되는 GitHub MCP 읽기 도구로 해당 이미지 디렉터리만 조회한다. 대소문자(`items`, `Echo`, `Weapons` 등), 공백, 확장자, NFC 한글, URL 인코딩, branch를 실제 파일명과 비교한다. NTE 파일명의 콜론은 기존 규칙에 따라 `_`인지 확인한다. 없는 경로를 반복 추측하기보다 상위 목록을 한 번 확인한다.
4. 필요하면 최종 이미지 URL의 응답·타입·캐시와 브라우저 로딩을 확인한다. HTTP 200만으로 올바른 이미지라고 판단하지 않는다. fallback이 그려진 것과 원본 이미지 성공을 구분한다. CDN 캐시 삭제·전체 preload·버전 무작위 변경은 진단을 대신하지 않는다.
5. Notion 확인을 요청받았다면 관련 레코드/속성만 읽어 대조한다. 동기화는 별도 명시 요청이 있을 때 공식 범위 지정 스크립트로 실행한다. 도구가 없으면 그 사실을 밝히고 기존 허용된 SDK/API를 쓰되 토큰·환경 변수 값·서명 URL을 출력하지 않는다. 연결·권한 설정을 임의 변경하지 않는다.

## 수정 요청이 포함된 경우

원인을 해결하는 최소 변경을 하고 같은 경로의 오류에 대한 회귀 테스트를 추가한다. 로컬 원본·Notion 정보·중복 방지 규칙을 보존한다. 전체 재동기화나 unrelated 캐릭터 내용 변경은 하지 않는다. 생성기가 수정 결과를 덮어쓰지 않도록 원본 변환 경로를 고친 뒤 필요한 런타임을 재생성하고 diff를 확인한다.

`AGENTS.md`의 필수 타입·테스트·build·diff·Git/배포 절차를 따른다. 최종 브라우저에서 원본 이미지, 라벨·수량·비율과 기존 여백을 확인한다. 재시도/fallback 루프나 이미지 완료를 기다리는 페이지 전환 차단을 만들지 않는다. 시각 수정 시에만 `DESIGN.md`를 읽고, 로딩 성능 조사 시에만 `docs/guides/PERFORMANCE.md`를 추가로 읽는다.

## 보고

원인·비교한 원본·바꾼 경로·실제 이미지 확인 결과·미검증 항목을 짧게 설명한다. 수정했다면 검증과 commit·push·배포 결과도 보고한다. 조회 성공을 동기화 성공이나 운영 반영으로 표현하지 않는다.
