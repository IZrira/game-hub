# 성능점검

호출: `성능점검` 또는 `$rira-performance-check`. RIRA 프로젝트 원본은 `D:\rira game hub\game-hub`이며 다른 경로에서는 Git remote가 `IZrira/game-hub`인지 확인한다.

AGENTS.md, docs/guides/PERFORMANCE.md와 git status를 확인한다. 대상 URL·commit·기능과 측정 도구를 고정한다. 진단만 요청하면 코드·캐시·운영 데이터는 변경하지 않는다.

1. 문제를 재현하고 네트워크 대기, 데이터·번역 다운로드, 이미지 요청/디코딩, React 렌더·메인 스레드를 구분한다. 관련 경로의 요청·전이 import부터 추적하고 매번 전체 저장소를 스캔하지 않는다.
2. 전후 비교는 같은 viewport·네트워크·CPU·광고 조건에서 cold/warm cache를 구분해 반복하고 중앙값을 사용한다. 도구가 없으면 측정 불가로 남긴다. 추정 gzip·실제 전송량·실험실 지표·현장 지표를 섞지 않는다.
3. 범위에 맞는 최소 수정을 제안한다. 이미지 도착까지 페이지 이동을 막지 않고, 전체 DB 정적 import·전체 preload·무한 재시도·캐시 무작위 무효화를 새로 만들지 않는다. 기능·원본 콘텐츠·광고·접근성 제거로 수치만 개선하지 않는다.
4. 수정 요청이 있으면 해당 병목과 회귀 테스트만 고친다. 현재 스크립트와 AGENTS.md에 따라 타입·테스트·build·diff를 검증한다. 빌드에 포함된 perf:audit·SEO 감사는 이유 없이 다시 실행하지 않는다. 예산을 올려 통과시키거나 Notion 동기화를 임의 실행하지 않는다.
5. 실제 브라우저에서 동일 사용 흐름과 이미지·레이아웃을 다시 확인한다. 테스트 통과만으로 체감 속도 개선을 주장하지 않는다. 단일 실행이나 TBT로 INP 통과를 확정하지 않는다.

운영 부하·침투 테스트, 추가 계측 서비스·브라우저 확장 설치, 사용자 추적 또는 보안 헤더 변경은 별도 범위 확인 전 실행하지 않는다.

측정 조건·전후 값·병목 근거·기능 보존·검증/배포 결과·미측정 항목을 짧게 보고한다. 객관적인 전후 측정 없이 절감률·9.5점 같은 점수를 만들지 않는다.

참고가 필요할 때만 [agent-skills의 성능·디버깅 원본](https://github.com/addyosmani/agent-skills)을 확인한다. 전체 개발 플러그인이나 자동 훅을 설치하지 않는다.
