- 작성일: 2026-11-10
- 근거: `npm run ui:audit` 측정(2026-11-10 로컬 빌드, 8개 화면 × 데스크톱·모바일)과 평가 보고서

남은 항목은 6개다. 1~4는 접근성 보완이라 화면 모양이 거의 바뀌지 않는다. 5·6은 화면 구성이 바뀌므로 결정이 필요하다.

1. 본문 바로가기 링크(skip link) 추가 — 결정 불필요
2. 제목 단계 정리 — 결정 불필요
3. 모바일 헤더 버튼 이름 한국어화 — 결정 불필요
4. 이름 없는 링크 5개 확인·수정 — 결정 불필요
5. 캐릭터 상세 첫 화면에 이름 보이기 — `[?]` 결정 필요
6. 추천 파티 화면 11px 보조 글자 — `[?]` 결정 필요

1~4는 한 번에 작업하고 push 1번으로 묶는다. 5·6은 결정 뒤 따로 한다.

## 1. 본문 바로가기 링크

- 문제: 키보드 사용자가 매번 헤더 메뉴 6개(로고, 홈, 통합 검색, 언어, 앱, 로그인)와 빵부스러기를 지나야 본문에 닿는다. 8개 화면 모두 해당.
- 제안
  - `common-hub/components/Layout.tsx`의 `<main>`에 `id="main-content"`와 `tabIndex={-1}`을 준다.
  - `<Navbar />` 앞에 "본문으로 바로가기" 링크를 둔다. 평소에는 숨기고(`sr-only`), Tab으로 포커스를 받으면 왼쪽 위에 보이게 한다(`focus:not-sr-only focus:fixed focus:left-4 focus:top-4 focus:z-[100]`, 배경 `#121212`, 테두리, 글자 14px).
  - 문구는 번역 키 `본문으로 바로가기`로 넣어 영어·일본어 화면도 같은 구조를 쓴다.
- 확인: `ui:audit`에 skip link 존재 여부 항목이 이미 있다. 첫 Tab에서 링크가 보이고 Enter 뒤 포커스가 `<main>`으로 가는지 헤드리스 Chrome으로 확인한다.

## 2. 제목 단계 정리

- 문제(측정): 제목 단계가 건너뛰는 곳이 있다. 화면 읽기 프로그램 사용자는 제목 목록으로 페이지 구조를 파악한다.
  - 캐릭터 상세(아케론): h2 → h4 2곳, h2 → h5 1곳. 스킬 이름(`h4`)과 성혼 이름(`h5`)이 섹션 제목(`h2`) 바로 아래에 있다.
  - 추천 파티: h1 → h4. 파티 카드 제목이 `h4`다.
  - 홈: h2 → h4 1곳.
- 제안
  - 화면 모양은 그대로 두고 태그 단계만 맞춘다. 글자 크기는 클래스로 정해져 있어 바뀌지 않는다.
  - `hsr-hub/components/SkillAndEidolonSection.tsx` 등 스킬 섹션: 스킬 이름 `h4` → `h3`, 성혼·공명 체인 이름 `h5` → `h3`(같은 섹션 아래 항목). WW `WuwaSkillSection.tsx`, NTE `NTESkillAndAwakeningSection.tsx`도 같은 구조를 확인해 맞춘다.
  - `common-hub/components/PartyBrowser.tsx`: 파티 카드 제목 `h4` → `h2`(페이지 h1 바로 아래 목록). 카드 안 하위 제목이 있으면 `h3`.
  - 홈(`common-hub/pages/Home.tsx`): 건너뛰는 1곳을 `h3`으로.
- 확인: `ui:audit`의 제목 건너뜀 0. 기존 렌더링 테스트가 `getByRole('heading', { level })`로 찾는 곳이 있으면 함께 고친다.

## 3. 모바일 헤더 버튼 이름 한국어화

- 문제: `common-hub/components/Navbar.tsx`의 아이콘 버튼 이름이 영어로 고정돼 있다. 한국어 화면에서 화면 읽기 프로그램이 "Search", "Change Language", "Toggle Navigation Menu"라고 읽는다.
  - 136줄 `aria-label="Search"`
  - 146줄 `aria-label="Change Language"`
  - 155줄 `aria-label="Toggle Navigation Menu"`
- 제안: `t('통합 검색')`, `t('언어 변경')`, `t('메뉴 열기')`/`t('메뉴 닫기')`(열림 상태에 따라)로 바꾸고 `aria-expanded`를 함께 준다. `ko.json`·`en.json`·`ja.json`에 키를 추가한다.
- 함께: `PageHeader.tsx`의 고정 토글 버튼은 `title`만 있고 `aria-label`이 없다. 같은 문구로 `aria-label`과 `aria-pressed`를 준다.

## 4. 이름 없는 링크 5개

- 문제: 모바일 HSR 세팅 공략과 NTE 공략 화면에서 접근 가능한 이름이 없는 링크가 5개씩 측정됐다. 데스크톱에서는 0개다. 모바일에서만 보이는 아이콘·이미지 링크로 추정한다(원인은 아직 확인하지 않음).
- 제안
  - 먼저 `ui:audit`이 이름 없는 링크의 위치(`outerHTML` 앞부분)를 기록하도록 고쳐 정확한 요소를 찾는다.
  - 이미지만 있는 링크면 이미지 `alt`를 캐릭터·장비 이름으로 채우거나 링크에 `aria-label`을 준다. 장식용 링크 중복이면 `aria-hidden`과 `tabIndex={-1}`로 같은 목적지의 다른 링크에 맡긴다.
- 확인: 모바일 공략 화면의 이름 없음 0.

## 5. 캐릭터 상세 첫 화면에 이름 보이기 `[?]`

- 문제: 데스크톱(1440×900) 캐릭터 상세 첫 화면에서 캐릭터 이름(H1)이 대표 이미지 맨 아래에 걸려 거의 보이지 않는다. 첫 화면에 보이는 것은 기본 스탯이다. `DESIGN.md` 4장의 "현재 위치와 제목 → 핵심 정보" 순서와 다르다. HSR·WW·NTE 캐릭터 상세 모두 같은 구조다.
- 선택지
  - 제안 A(추천): 대표 이미지 영역의 높이를 데스크톱에서 화면 높이에 맞춘다(예: `max-h-[calc(100dvh-14rem)]`, 이미지는 `object-cover`로 위쪽 기준). 이름·속성·세팅 공략 버튼이 첫 화면 안에 들어온다. 레이아웃 구조는 그대로다.
  - 제안 B: 이름·속성·세팅 공략 버튼을 이미지 위 오버레이에서 빼서 빵부스러기 아래 제목 줄로 옮긴다. 정보 순서는 가장 명확하지만 상세 화면 3종의 첫인상이 바뀐다.
  - 제안 C: 그대로 둔다. 모바일은 이미 이름이 먼저 보인다.
- 확인: 1440×900, 1280×720, 390×844에서 첫 화면 캡처로 이름이 보이는지 확인한다.

## 6. 추천 파티 화면 11px 보조 글자 `[?]`

- 현황: 9·10px는 없어졌지만, 추천 파티 화면에는 11px 글자가 모바일 219개, 데스크톱 387개 남아 있다. 대부분 캐릭터 초상 아래 역할 라벨("메인 딜러", "서포터")과 대체 캐릭터 칩이다. 정한 기준(보조 표시 11px 허용) 안이다.
- 선택지
  - 제안 A: 역할 라벨만 12px로 올린다. 4명이 한 줄에 들어가는 모바일 카드에서 "메인 딜러"가 줄바꿈되지 않는지 320px로 확인한다.
  - 제안 B(추천): 그대로 둔다. 캐릭터 이름(12px 이상)이 정보이고 역할 라벨은 보조 표시라 기준에 맞는다. 다른 화면과의 일관성도 유지된다.

## 검증 계획 (1~4 공통)

1. `npm run typecheck`
2. `npm_config_ignore_scripts=true npm run build`(Notion 동기화 없음)
3. `npx vitest run`
4. 로컬 빌드로 `npm run ui:audit` 8개 화면 측정. 목표: 제목 건너뜀 0, 이름 없음 0, skip link 있음, 포커스 표시 유지
5. 첫 Tab 화면과 메뉴 버튼 캡처 확인
6. `git diff --check`, `git diff`, commit, push, CI·Cloudflare 확인
