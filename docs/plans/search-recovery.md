## 3. 작업 목록

각 항목은 별도 commit으로 처리하고 `AGENTS.md`의 검증·push·배포 확인을 따른다.

### 결정 없이 바로 할 수 있는 작업

- [x] R1. 사이트맵 `lastmod`를 실제 변경일로 (2026-11-08, commit hash는 Git 기록 참고)
  - 원인: 파일 기반 `lastmod`가 파일 수정 시각(mtime)이었다. Cloudflare Pages는 빌드할 commit 하나만 새로 받으므로 모든 파일의 수정 시각이 빌드 날짜가 됐다. 사이트맵 색인의 날짜 없는 사이트맵에도 빌드 날짜를 넣었다.
  - 변경: 파일 기반 날짜는 그 파일을 마지막으로 바꾼 commit 날짜를 쓴다. Cloudflare 빌드에서 기록이 얕으면 전체 기록을 한 번 받는다(약 17MiB). 받지 못하거나 Cloudflare 밖의 얕은 기록(GitHub Actions)이면 파일 기반 `lastmod`를 뺀다. 공략 `reviewedAt`, 애니모 `checkedAt`, 블로그·공지 날짜는 그대로다. 날짜 없는 사이트맵은 색인에서 `lastmod`를 뺀다.
  - 확인: 연속 생성 2회 결과 동일, 파일 수정 시각을 바꿔도 결과 동일. 얕은 복제에서 `CF_PAGES=1`로 생성한 결과가 로컬과 같다. 표본(HSR 캐릭터·가이드, 유물, 애니모 서식지)의 날짜가 `git log` 날짜와 일치.
  - 남은 한계: 장비·WW 가이드처럼 한 파일에 여러 항목이 있으면 그 파일이 바뀔 때 모든 항목 날짜가 함께 바뀐다. 광추·Notion 항목(NTE 캐릭터·아크, WW 에코)은 날짜 정보가 없어 `lastmod`가 없다.
- [ ] R2. 크롤링 리소스 부담 측정

  - 초기 HTML만으로 본문·내부 링크가 충분한지 다시 확인한다(빌드 SEO 감사 결과 재사용).
  - 개선은 측정 결과를 보고 별도 항목으로 만든다. 측정 전에 코드를 바꾸지 않는다.
