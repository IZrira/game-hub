## 2. 결정 사항

### 페이지 처리

- 장비 페이지는 noindex하지 않고 보강한다. 장비 검색 유입이 있기 때문이다.
  - 상세 페이지에 화면에서만 보이던 "이 장비를 추천하는 캐릭터"를 사전 렌더링 HTML에도 넣는다. 캐릭터 공략에서의 순위·조건도 함께 넣는다.
  - 어떤 캐릭터 공략에서도 추천되지 않는 장비만 noindex하고 사이트맵에서 뺀다.
- HSR·WW·NTE 캐릭터와 캐릭터별 세팅·공략 페이지는 대표 콘텐츠로 유지한다.
- Aniimo 도감·지역 페이지는 노출을 유지한다(유입 1위).
  - 외부 "공식 위키" 링크를 "공식 도감 기준 · 확인일" 문구로 바꾼다(`AGENTS.md` 규칙 8).
  - 진화 단계·상성·출현 지역 등 사이트 자체 연결 정보가 잘 보이는지 점검한다.
- 값이 "추후 추가"인 칸은 화면에 표시하지 않는다.

### 콘텐츠

- 새 글보다 기존 공략 보강을 먼저 한다.
- 보강 순서는 다음과 같다.
  1. Aniimo 지역 페이지 점검과 보강
  2. NTE 공략 26편(감정사·다포딜부터)
  3. 노출이 많은 HSR·WW 캐릭터 세팅 공략
- 세팅 공략 보강 기준은 글자 수가 아니라 다음 세 가지다.
  - 추천 항목(장비·유물·무기·에코·파티)마다 "왜 이 캐릭터에게 맞는지" 근거 문장 1~2개
  - 상황별 대안 조건(무과금, 대체 캐릭터 등)
  - 게임 버전과 확인일
- 작업 분담은 다음과 같다.
  - 에이전트: 저장소 데이터로 사실을 확인하고 초안을 쓴다.
  - 사용자: 추천 대상·우선순위에 대한 판단 메모를 주고 최종 검수한다.
  - 사용자가 주지 않은 체감·경험담은 쓰지 않는다.
- `/blog`는 410을 유지하고, 새 글은 `/gallery/:gameId/guides`에 올린다.
- 메커니즘 분석 글의 템플릿 설계는 이번 범위에서 빼고 승인 뒤 별도로 진행한다. 아이디어는 보강 작업 중 메모로 모은다.
- HSR·WW 캐릭터·공략 페이지의 검색 제목과 설명을 실제 검색어 형태("○○ 유물", "○○ 세팅 최신" 등)에 맞게 다듬는다.

### 신뢰·정책

- 공략마다 확인 근거(게임 버전, 확인일, "게임 내 확인")를 내부 데이터에 채운다. 공개 화면에는 외부 사이트 이름 없이 "게임 내 정보 기준 · 확인일"만 표시한다. 근거를 채울 수 없는 글은 "출처 확인" 문구를 실제 상태에 맞게 고친다.
- Google 인증 동의 관리 도구(CMP)를 도입한다.
  - AdSense 콘솔의 개인정보 보호 및 메시지 설정은 사용자가 한다.
  - 자체 `CookieBanner`의 "계속 이용 시 동의 간주" 방식은 에이전트가 정리한다.
- 개인정보처리방침의 "DART 쿠키" 표현을 현행 Google 안내 문구와 링크로 바꾼다.
- `public/ads.txt` 앞의 BOM을 제거한다.
- `slot`이 전달되지 않는 `AdPlaceholder` 사용처를 정리한다. 수동 광고 단위를 쓸 계획이 생기면 다시 판단한다.

### Search Console

- Soft 404 9개의 원인을 고친 뒤 사용자가 Search Console에서 "수정 확인"을 누른다.
- "발견됨 - 현재 색인 생성 안 됨" 553개는 색인 요청을 일괄로 보내지 않는다. 내부 링크와 품질 보강으로 재수집을 기다린다.
- 확인은 사용자가 내장 브라우저에 로그인하고 에이전트가 읽기만 하는 방식으로 한다. 속성은 URL 접두어 `https://riragamehub.com/`이다.
