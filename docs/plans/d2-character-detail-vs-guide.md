# D2 제안서: 캐릭터 상세와 세팅 가이드의 역할 분리

- 작성일: 2026-11-09
- 대상: HSR 캐릭터 상세 94개와 가이드 93개, WW 캐릭터 상세 56개와 가이드 54개
- 근거 자료: 운영 사이트 초기 HTML(빌드 결과), Search Console 실적(2026-05-01~11-07, 페이지·검색어 단위)

## 1. 문제 요약

한 캐릭터에 두 페이지가 있고, 두 페이지가 같은 검색어("○○ 세팅", "○○ 종결", "○○ 공략")를 노린다. Google은 같은 사이트에서 같은 의도의 페이지가 둘이면 하나를 고르거나 둘 다 낮게 평가한다. 클릭은 가이드에서 나오는데, 상세 페이지가 같은 검색어로 노출을 나눠 가져간다.

## 2. 근거

### 제목·H1이 같은 검색어를 노린다

- 아케론 상세 제목: "아케론 캐릭터 공략 및 세팅 정보"
- 아케론 상세 H1: "아케론 상세 정보 & 종결 육성 가이드"
- 아케론 가이드 제목: "스타레일 아케론 공략 | 추천 광추 · 유물 세팅 · 목표 스탯 · 파티 조합 · 운용 분석"
- 아케론 가이드 H1: "붕괴: 스타레일 아케론 종결 육성 공략 가이드"
- WW도 같다. 카르티시아 상세 H1은 "명조 카르티시아 상세 정보 & 종결 육성 가이드"다.
- 상세 페이지의 "공략", "세팅", "종결 육성 가이드"가 가이드와 겹친다.

### 상세 페이지 초기 HTML이 가이드보다 세팅 내용이 많다

- 아케론 상세의 초기 HTML 순서: 세팅 요약 → 기본 능력치 → 추천 광추 순위 → 추천 유물·차원 장신구 → 추천 파티 조합 → 스킬·행적 → 성혼
- 본문 글자 수(초기 HTML): 아케론 상세 3,660자, 아케론 가이드 2,138자
- 카르티시아 상세 8,866자, 카르티시아 가이드 1,131자
- Google이 먼저 읽는 HTML에서는 상세 페이지가 가이드보다 더 "세팅 공략"처럼 보인다.

### 실적은 가이드에 몰린다

검색어 단위 자료는 Google이 저빈도 검색어를 숨겨서 실제보다 적게 잡힌다. 경향만 본다.

- HSR 상세: 클릭 1, 노출 172, 평균 순위 10.0
- HSR 가이드: 클릭 8, 노출 534, 평균 순위 8.4
- WW 상세: 클릭 0, 노출 50, 평균 순위 10.7
- WW 가이드: 클릭 4, 노출 367, 평균 순위 10.4
- 페이지 단위(2026-09-14~10-26): HSR 상세 94개 중 54개가 노출을 받았지만 클릭 6, 같은 캐릭터 가이드는 클릭 38
- 상세 페이지 노출을 만든 검색어는 대부분 "세팅"·"종결"이다. 예: "어벤츄린 웨이브 세팅", "케리드라 세팅", "명조 설지 세팅"
- 상세 페이지만 받는 다른 검색어는 적다. 예: "능양 성우", "복링 성우", "알토 사이클"

### 해석

- 상세 페이지는 세팅 검색어에서 노출되지만 클릭을 거의 받지 못한다. 사용자가 원하는 답(세팅)이 가이드에 더 잘 정리되어 있기 때문으로 본다.
- 같은 검색어에 상세가 노출되는 만큼 가이드의 노출 기회가 줄어든다.
- 상세 페이지 고유의 수요(스킬, 성혼·공명 체인, 육성 재료, 성우·프로필)는 실제로 있다. 상세 페이지를 없앨 이유는 아니다.

## 3. 선택지

### A. 역할 분리 (추천)

- 상세 = 도감: 스킬, 성혼·공명 체인, 육성 재료, 능력치, 프로필·성우
- 가이드 = 세팅 공략: 추천 장비, 유물·에코, 목표 스탯, 파티, 운용
- 1단계(메타데이터):
  - 상세 페이지의 제목, H1, 설명에서 "공략", "세팅", "종결 육성 가이드"를 뺀다.
  - 예시 제목: "아케론 스킬·성혼·육성 재료 | 붕괴: 스타레일 캐릭터 도감"
  - 예시 H1: "아케론 캐릭터 정보"
  - 상세 페이지 상단의 가이드 링크 문구를 "아케론 세팅 공략 보기"처럼 분명하게 한다.
- 2단계(초기 HTML 순서):
  - 상세 페이지 초기 HTML에서 도감 정보(능력치, 스킬, 성혼)를 앞으로 옮긴다.
  - 세팅 부분은 "세팅 요약" 몇 줄과 가이드 링크로 줄인다.
  - 화면(앱)의 섹션 구성은 바꾸지 않는다. Google이 먼저 읽는 HTML의 순서와 비중만 바꾼다.
- 장점: 두 페이지 모두 색인을 유지한다. 상세 고유 검색어(스킬, 성우)를 지킨다. 되돌리기 쉽다.
- 단점: 효과가 나타나기까지 몇 주 걸리고 크기를 보장할 수 없다.
- 작업량: 1단계는 제목 생성 코드 2곳과 초기 HTML 생성 2곳이다(`common-hub/utils/guideSeo.js`, `common-hub/utils/wwCharacterSeo.js`, `scripts/prerender-meta.js`). 2단계는 `scripts/prerender-meta.js`의 상세 페이지 HTML 순서만 바꾼다.

### B. 가이드가 있는 캐릭터의 상세 페이지 noindex

- 147개 페이지(HSR 93, WW 54)를 색인과 사이트맵에서 뺀다. 페이지는 그대로 열린다.
- 장점: 겹침이 즉시 사라진다. 평가 대상 페이지가 줄어든다.
- 단점: 상세 고유 검색어(스킬, 성우, 사이클)를 잃는다. 도감으로서의 실제 내용도 검색에서 빠진다. 되돌린 뒤 다시 색인되기까지 오래 걸린다.

### C. 상세 → 가이드 canonical 지정

- 추천하지 않는다. 두 페이지 내용이 다르면 Google이 canonical을 무시하는 경우가 많고, 잘못된 신호가 된다.

## 4. 추천: A안, 1단계부터

1. 1단계(메타데이터)를 HSR·WW에 함께 적용한다. 화면 변화가 거의 없고 위험이 가장 낮다.
2. 2단계(초기 HTML 순서)도 함께 적용하는 것을 권한다. 상세의 초기 HTML이 세팅 내용으로 시작하는 것이 겹침의 핵심 원인이라, 1단계만으로는 효과가 약할 수 있다.
3. 4주 뒤 Search Console에서 확인한다.
   - 확인할 값: "세팅·종결" 검색어의 노출이 가이드 쪽으로 옮겨 갔는지
   - 확인할 값: 상세 페이지가 "스킬·성우·재료" 검색어 노출을 유지하는지
   - 효과가 없으면 B안을 다시 검토한다.

## 5. 지키는 것

- 공개 URL, 페이지 존재, 내부 링크는 바꾸지 않는다.
- 화면에 없는 내용을 초기 HTML이나 구조화 데이터에 새로 만들지 않는다. 기존 내용의 순서와 제목만 바꾼다.
- NTE도 같은 문제가 있다. 잔홍 상세 제목은 "잔홍 종결 세팅 · 추천 파티 조합 & 스킬 매커니즘"이고, 세팅 공략 제목은 초기 HTML에서 "잔홍 세팅 공략", 앱 실행 후 "이환 잔홍 공략 | 아크 · 콘솔 세팅 · 육성 우선순위"다. 다만 NTE 상세 24개 중 노출을 받은 것은 3개뿐이라 실적 근거가 적다. HSR·WW에 적용한 뒤 같은 방식으로 함께 정리하는 것을 권한다.

## 6. 결정이 필요한 것

- A안을 적용할지, 적용한다면 1단계만 할지 1·2단계를 함께 할지
- NTE 캐릭터 상세도 함께 적용할지
- 예시 제목 형식("○○ 스킬·성혼·육성 재료 | 붕괴: 스타레일 캐릭터 도감")을 그대로 쓸지
